# Hnefatafl 0.25.0

Training configuration reuse and actual self-play statistics. The stable release
and annotated tag use **0.25.0**.

## Delivered behavior

- **Use parameters** on running, queued, completed, cancelled or failed jobs
  opens and populates the new-training form and Advanced configuration, scrolls
  it into view and identifies the source. Every supported value remains editable;
  copying does not start work or change the source job.
- Job and model loading share an allowlisted validator for network, optimizer,
  search, evaluation, seed, checkpoint/budget, preset and inference settings.
  Explicit zero/false survive. Legacy missing values retain current inputs;
  invalid values and unavailable hardware receive safe fallbacks with warnings.
  Execution paths, resume references and credentials are excluded. Reuse defaults
  to this server; users can select another execution target before starting.
- Tuning restores nested training inputs, valid search space, trial budget,
  study name and independently editable study seed. Starting creates a fresh
  study database; continuing the original study still uses **Resume study**.
- Job navigation shows actual generated games compactly. The selected summary
  separates **Job games** from **Cumulative training games**. Model cards show
  **Total self-play games** separately from games configured per iteration.
  English/German labels and locale-aware totals are included.
- Versioned optional `self_play_games` metadata records job contribution, input
  checkpoint baseline and cumulative lineage. Local/remote progress, cancelled
  and failed checkpoints, job ZIPs and model exports retain recorded counters.
  Best models keep the count captured with their own selected weights.

## Counter semantics and compatibility

If A generates 4,000 games, and B resumes A and generates 2,000 more, B displays
2,000 job games and 6,000 cumulative games. Every resume takes a fresh baseline
from its original input checkpoint. An earlier best-model checkpoint keeps its
earlier total. Generated maximum-ply games count; evaluation, tournament and
interactive games do not. Totals are never calculated from configured budgets.

No database migration, neural architecture, training algorithm or tensor format
change is required. Existing tensor-format-1 checkpoints remain loadable. Legacy
`games_generated` retains its cumulative meaning; it is nullable when a resumed
checkpoint has no recorded lineage baseline. The new job contribution remains
known in that case. Old inference models without counters show **Not recorded**.
Legacy resumed/imported jobs without a baseline cannot establish a job-local
total. Historical files and registry entries are not rewritten automatically.

Update remote workers to 0.25.0 for the new metadata. Older worker progress can
still supply its actual cumulative counter; unavailable job contributions remain
explicit. Tuning only retained current-trial progress, so reliable complete
study-wide aggregation is unavailable and displayed as **Not recorded**.

## Installation and update

Use the stable `0.25.0` GitHub release's installer-compatible
`hnefatafl-0.25.0.tar.gz` asset. The release workflow packages the exact clean
tagged source after successful Verify CI and verifies GitHub's SHA-256 asset
digest. Automatic GitHub source archives are not production updater inputs.
Follow [deployment and backups](../DEPLOYMENT.md) and [release packaging](../RELEASING.md).

## Limitations

CPU functional checks do not demonstrate stronger play or GPU acceleration.
CUDA, Apple MPS and physical Intel GPU execution are unverified on this host;
device compatibility fallbacks are tested with reported-capability fixtures.
Unknown historical totals cannot be reconstructed faithfully. Physical mobile
devices and production systemd/Proxmox deployment were not exercised.
