# 0.33.0 - Responsive play, personal statistics and online clocks

This feature release builds on `0.32.0` with a shared desktop/mobile play and
replay layout, detailed personal statistics, compact Dashboard badges, configurable
online clocks and consistent interface styles.

Upgrading from `0.32.0` advances SQLite from schema **12 to 13**. Automatic timeout
losses now default to enabled. Review the timeout controls below before upgrading
a deployment with unfinished online games; clocks are not extended for downtime.

## Added features

### Personal statistics and Dashboard badges

- A dedicated **Statistics** page separates Singleplayer and Multiplayer results
  by ruleset, with overall, attacker and defender comparisons for games played,
  wins, losses, draws, win rate and average game length. Singleplayer also offers
  expandable AI-opponent breakdowns; equivalent configurations group across seeds.
- Mode and ruleset selections survive navigation, login and reload through the
  URL. On phones, labelled metric cards replace wide tables.
- Dashboard replaces detailed statistics cards with compact ruleset badges that
  link to the corresponding statistics. Singleplayer decorations reflect current
  win-rate tiers; multiplayer shows the existing ruleset Elo when games have been
  played. Empty results show an em dash. These badges add no rewards or new rating
  policy; all aggregates remain scoped to the signed-in account.

See [Dashboard and statistics](../DASHBOARD.md).

### Shared play and replay screens

- **Play** in the site menu resumes the last selected unfinished game when it is
  still available, otherwise another running game. With none, it offers the same
  creation dialogs as Dashboard. Account changes and logout clear the selection.
- Singleplayer, online games and Hall reviews share the board, player summary and
  **Moves / Analytics / My games** layout. Phones keep the board visible above a
  tabbed panel; landscape places the panel beside it. Desktop uses the available
  viewport with internally scrolling tab content, including shorter windows and
  all three interface scales.
- **My games** includes the current game and unfinished account/active or waiting
  online games. Games awaiting your move use the filled button style and retain
  the **Your turn** text; an independent outline marks the open game. The sole
  remaining game stays reachable after another finishes.
- Selecting a historical move shows a local, read-only position. It does not
  rewind or branch the authoritative game. **Return to live board**, or the
  latest recorded move, restores live play. AI turns run automatically at the
  live position and stop while browsing history; pause/resume, undo/redo, restart
  and new-game controls are removed from the play screen.
- Hall opens selected reviews in the shared layout. **Back to Hall** retains
  filters, pagination and the selected-record highlight. Replay navigation stays
  in Moves. Online games no longer show a separate **View replay** button;
  **Starting position** and recorded moves still open history.

Live online games continue to deny AI assistance. Completed-game analysis retains
its existing authorization and server-confirmed completion requirement.
See [gameplay](../GAMEPLAY.md) and [online play](../ONLINE_PLAY.md).

### Online time controls

- Creation offers **Per move** or **Total per player**, using a base limit from
  one minute to fourteen days, default three days. Total time gives each player
  a separate balance, consumed only during their own turns.
- Total-time games optionally add a whole-seconds increment after each timely
  move. The increment is shown only for total time; switching to per-move clears
  it, and new per-move requests submit zero. Existing games and retained uncertain
  creation requests keep their exact settings and request IDs.
- Both player clocks appear on mobile; Game options shows the configured clock
  details. Each leg of a two-game match starts with fresh clocks.
- The server finalizes expired clocks as losses and updates ratings. The browser
  waits for that authoritative result and never declares a timeout itself.
  Request-time and background finalization respect the same operator gates;
  the default background interval is now one second.

See [online clocks](../ONLINE_PLAY.md#connection-and-time) and
[operator controls](../ONLINE.md#pause-inspect-resolve-and-resume).

## Interface changes and fixes

- All screens use the shared responsive site menu, including mobile play. Common
  CSS classes and typography tokens unify buttons, headings, dialogs, tabs,
  surfaces and form controls across game and administration screens.
- Page titles and subtitles remain accessible to screen readers and focus
  navigation without consuming visible space. Section headings, dialog titles
  and error messages remain visible.
- The online creation dialog uses two desktop columns for game and clock settings
  and stacks them on phones. Redundant clock explanation labels are removed.
  **Concede** uses the normal secondary button style and retains confirmation.
- Dashboard places its email-verification warning near the top and disables new
  online creation for unverified accounts; existing admitted seats retain their
  current play permissions. Duplicate lobby copy is removed.
- Automatic AI retry timing resets for a newly selected game. Desktop column
  spacing, short-window replay, phone landscape controls and move-history sizing
  are corrected. The README gameplay image uses the wood appearance.

## Upgrade and installation

1. Stop/cancel active training and tournaments and pause remote claim loops. For
   existing online games, explicitly pause the persistent timeout gate before
   maintenance. Take a complete stopped-writer backup of the data root and
   protected configuration, retaining matching `0.32.0` code.
2. After `0.33.0` is published as a stable release with its verified archive digest,
   use the production updater:

   ```sh
   hnefatafl-update --check
   hnefatafl-backup
   hnefatafl-update --version 0.33.0
   ```

   On a Proxmox host, prefix these commands with `pct exec <CTID> --`. Fresh
   installations follow [Deployment](../DEPLOYMENT.md). A branch, tag or GitHub
   automatic source archive is not a production installation asset.
3. Confirm schema **13** and application readiness. Migration adds immutable
   clock settings and per-player balances. Existing games remain per-move with
   zero increment and retain their original deadlines. Accounts, ownership,
   histories, ratings, training data and model formats are preserved.
4. Review both timeout controls before resuming play. The environment default for
   `HNEFATAFL_ONLINE_TIMEOUT_POLICY_APPROVED` changes to **true**; an explicitly
   configured **false** remains effective. Migration enables only the untouched
   legacy disabled gate at version 0 and records an audit entry. Explicit
   administrator and restore pauses remain paused. Resume deliberately after
   reviewing expired games; no deadline extension is applied automatically.
5. Update remote workers to **0.33.0** before assigning new work. Exact application
   version and existing compatibility checks still apply; this release adds no
   worker protocol or model/checkpoint migration. Registration and new online
   admission keep their separate disabled-by-default configuration.

Schema-12 code cannot safely read schema 13. Automatic recovery across different
online schemas/columns fails closed; retain the pre-upgrade backup for a separately
reviewed rollback or use forward repair. Compatible schema-13 recovery preserves
current authoritative online/security state, revokes sessions and other recovery
capabilities, and pauses timeout finalization. Review
[migration and recovery](../ONLINE.md#migration-backup-and-recovery) and
[worker upgrades](../REMOTE_TRAINING.md#application-compatibility-and-upgrades).
For upgrades older than `0.32.0`, also follow that release's
[account preflight and migration instructions](0.32.0.md#upgrade-and-installation).

## Limitations

- Online clocks continue during disconnection, logout and server outages. Operator
  pauses stop finalization, not elapsed time. No automatic deadline compensation,
  waiting-game expiry, aggregate match score or matchmaking is added.
- Play requires an authenticated server connection. Anonymous/offline play is not
  included. SMTP deliverability and target-host production deployment remain
  operator validation.
- Browser coverage uses Chromium and phone emulation. Physical Safari and
  classic-scrollbar desktops were not established by these runs. CUDA and Intel
  OpenVINO GPU execution remain unverified where hardware is unavailable.
- Statistics badges are cosmetic; this release makes no stronger-AI claim and
  includes no new pretrained model. Winning-chance displays remain uncalibrated
  position assessments.
