# 0.39.0 - Schedule-Free training and tournament benchmarking

This stable milestone adds optional Schedule-Free AdamW, more informative and
reproducible tournament comparisons, and evaluation charts fitted to their selected
series. It includes every change merged to `main` since published `0.38.0`:
[#65](https://github.com/freeDom-/hnefatafl/pull/65),
[#66](https://github.com/freeDom-/hnefatafl/pull/66) and
[#67](https://github.com/freeDom-/hnefatafl/pull/67), including their review fixes.

**Compatibility:** database schema **15**, checkpoint tensor format **1** and
job-archive schema **3** are unchanged. AdamW remains the default. Schedule-Free
requires the training extra, rejects HyperController, and preserves optimizer
identity and warm-up duration on resume. Update workers to **0.39.0** for the
existing exact-version policy; Schedule-Free jobs additionally require the new
`schedule_free_adamw` capability, even with an administrator version override.
CUDA and MPS execution remain unverified in the CPU implementation environment.

Full comparison: [`0.38.0...0.39.0`](https://github.com/freeDom-/hnefatafl/compare/0.38.0...0.39.0).

## Training and AI changes

### Optional Schedule-Free AdamW (#67)

- Choose **Schedule-Free AdamW** (`optimizer: "adamw_schedulefree"`) alongside
  AdamW, Adam and momentum SGD in training and Optuna studies. Existing defaults
  and presets retain AdamW. The training extra adds the maintained official
  `schedulefree>=1.4.1,<2` package, locked to **1.4.1**, under Apache-2.0.
- Gradient updates use training parameters; self-play, evaluation, Champion and
  best-model selection, inference snapshots and playable exports use the averaged
  evaluation parameters. Full checkpoints retain the upstream optimizer's moments,
  averaging history and counters together with replay, RNG/scaler, selection and
  training history for continuation.
- New `schedulefree_warmup_steps` accepts **0–1,000,000**, default **0**. It counts
  successful optimizer updates rather than training iterations; GradScaler-skipped
  updates do not advance it. The configured learning rate remains the base rate.
  Warm-up does not choose a base rate or enable HyperController automatically.
- Training creation, resumption, configuration import/export, model summaries and
  English/German help expose the new optimizer. Its status shows the base rate,
  last warm-up-adjusted rate, successful update count and warm-up progress without
  changing the meaning of existing learning-rate charts.
- Local training/tuning submissions execute an optimizer availability probe before
  allocating a job or subprocess. Missing or unusable dependencies return a field
  error without a silent fallback. Ordinary optimizers do not execute that probe;
  remote-only API servers rely on worker capabilities instead of needing the
  package installed locally.
- Workers advertise `schedule_free_adamw` only after a real tiny optimizer update
  and evaluation-mode probe succeeds. Older workers can still receive supported
  ordinary-optimizer jobs under existing version policy; inert new warm-up fields
  are omitted from their assignment/resume copies while original checkpoints stay
  intact. Existing non-Schedule-Free Optuna study identities remain resumable.
- Recoverable update failures and cancellation restore evaluation mode before
  saving. If an upstream mode transition itself fails, further mode/rate changes
  and new checkpoint writes are blocked, preserving the last valid checkpoint.
  Resume that checkpoint into a fresh optimizer instead of saving partially
  transitioned live weights.

**Configuration and resume:** use `adaptation: "off"`. Combining Schedule-Free
with HyperController is explicitly rejected in new/resumed jobs, tuning, imports
and remote assignment. Optimizer identity cannot change on resume. The resume
UI/API keeps warm-up duration read-only; the CLI rejects a duration change after
successful updates. Explicit base-rate and weight-decay overrides preserve moments
and averaging state. Existing model architecture, targets and game rules do not
change, and no playing-strength improvement is established.

See [Schedule-Free training and configuration](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/TRAINING.md#schedule-free-adamw),
[remote workers](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/REMOTE_TRAINING.md)
and [training data and continuation](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/TRAINING_DATA.md).

## Tournament and gameplay improvements

### Independent fixed-role opponents and useful sample counts (#66)

- Fixed-role comparisons now configure attackers and defenders independently with
  the regular participant editor: named profiles, heuristic agents, trained
  models and applicable MCTS/alpha-beta/no-search parameters. The same weights can
  occupy both seats with different search budgets, time limits or temperatures;
  each seat retains separate results. Previously exported shared-setting
  configurations remain valid.
- Model selectors remain usable while the catalog loads. Existing selections and
  search settings survive delayed responses; incompatible models remain visible
  until explicitly changed rather than being silently replaced.
- Standings show overall, attacker/defender and collapsible per-battlefield
  outcomes, win rates and score rates with completed-game sample counts. Win rate
  is wins/completed; score rate is (wins + half the rule draws)/completed.
  Move-limit truncations remain **unfinished**, outside both denominators.
  An unplayed or zero-completed role shows unavailable rates instead of a false 0%.
- Historical role statistics are reconstructed only when retained matches agree
  exactly with authoritative counters. Partial or contradictory histories retain
  their overall counts and show unavailable role detail, with the retained match
  count disclosed; missing evidence never fabricates a zero-sized sample.
- Search diagnostics distinguish configured MCTS budget, actual mean simulations,
  budget completion among eligible searches, immediate-win shortcuts and explicit
  deadline cutoffs. Immediate-win shortcuts are excluded from the budget-completion
  denominator. A search below budget is not automatically called a timeout.
  Historical records without the required counters omit those metrics instead of
  being reinterpreted under the corrected definitions.

### Optional reproducible legal openings (#66)

- Both tournament modes add **Randomize starting positions**, off by default,
  preserved by configuration import/export. Seeded opening version 1 generates
  **2, 4 or 6 legal plies** while retaining side to move and repetition history.
  It avoids captures, terminal/repeated positions and immediate winning replies;
  no model inference or participant search setting affects generation.
- Adjacent side-swapped round-robin legs use the same complete opening state.
  Fixed-role games keep their seats, and swapping opponents in a rerun with the
  same seed/settings reproduces the opening sequence. Different pairings in a
  multi-agent tournament have independent opening sets and additional sampling
  variance; randomized openings do not guarantee strategic balance.
- Openings are deduplicated up to board rotations/reflections. After bounded
  attempts, a suitable duplicate is explicitly marked; if no suitable opening
  exists, the run fails visibly while retaining earlier results. Generation is
  lazy and cancellable.
- Saved replays include and label the legal opening prefix and retain its seed,
  version and uniqueness. The move cap, decision timings and search diagnostics
  count **agent moves only**; total game length includes opening moves. Existing
  standard-start records remain replayable without migration.

See [tournament setup and interpretation](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/TOURNAMENTS.md),
[independent fixed-role configuration](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/TOURNAMENTS.md#fixed-role-comparison)
and [opening reproducibility and sampling limits](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/TOURNAMENTS.md#randomized-legal-openings).

## UI and usability improvements

### Fit evaluation charts to the selected series (#65)

- **Fit series** uses the selected evaluation context's first and last valid
  recorded observations for the horizontal range, using complete history rather
  than the full training span. It works with individual series, **Latest** and
  merged **All**, including sparse, resumed and unsorted imported histories.
- **Latest** follows the greatest valid recorded iteration, so a returning
  evaluation context becomes active again. Invalid newer observations cannot
  displace the latest valid context merely because of array or group order.
- Gaps, side scores, promotion markers, the fixed 0–100% evaluation scale and
  pointer/keyboard inspection remain available. Learning/Performance keep their
  shared numeric windows; job changes reset per-job selections. English/German
  labels and history-completeness disclosures accompany the new controls.

See [training dashboard charts](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/TRAINING_DASHBOARD.md).

## Benchmark evidence and hardware compatibility

The committed [CPU measurements](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/benchmarks/schedulefree-adamw.md)
and [raw results](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/benchmarks/schedulefree-adamw.json)
compare AdamW and Schedule-Free on a shared AMD EPYC 9V74 with Python 3.12.14,
PyTorch 2.14.1+cpu, schedulefree 1.4.1 and two threads. Each architecture/optimizer
case executes three repetitions of 16 updates, plus bounded real self-play and
evaluation. Checkpoints contain 8,000 independently cloned Brandubh replay positions.
All measured cases fit the unchanged **128 MiB** checkpoint limit; the largest
128-channel/eight-block Schedule-Free case is **48.734 MiB**. Arbitrary replay,
action-list and history retention can differ. Timing differences in these short
runs do not establish a general speedup or stronger models.

CUDA/MPS hardware was absent. Hardware-gated tests and an
[RTX 3060 FP32/AMP validation procedure](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/SCHEDULEFREE_CUDA.md)
cover continuation, skipped updates, Champion/export correctness and synchronized
throughput/memory measurement, but providing those commands is not execution
evidence. No GPU memory, throughput or strength result is claimed.

## Upgrade and installation

1. Stop/cancel training and tournaments, pause remote claim loops and unmanaged
   writers, and take a stopped-writer backup of the data root and protected
   configuration. Retain matching `0.38.0` code with that backup.
2. After stable publication and source-asset verification:

   ```sh
   hnefatafl-update --check
   hnefatafl-backup
   hnefatafl-update --version 0.39.0
   ```

   On Proxmox, prefix with `pct exec <CTID> --`. Use the attached
   `hnefatafl-0.39.0.tar.gz`, not GitHub's automatic source archive. Fresh installs
   follow [Deployment](https://github.com/freeDom-/hnefatafl/blob/0.39.0/docs/DEPLOYMENT.md).
3. Deploy backend and frontend together, confirm readiness and schema **15**, and
   check existing jobs, tournaments and replays. No database migration is added;
   checkpoint tensor format **1** and job-archive schema **3** remain unchanged.
4. Update workers to **0.39.0** before new assignments. Install the training extra
   on execution hosts for Schedule-Free and confirm `schedule_free_adamw` capability.
   Keep HyperController off for that optimizer and preserve resume identity/warm-up
   settings. Older binaries cannot execute a Schedule-Free checkpoint merely
   because its tensor container format is unchanged.
5. Resume writers and claim loops after readiness and compatibility checks.

## Limitations

- Schedule-Free needs workload-specific learning-rate/warm-up experiments. It
  neither enables HyperController nor provides evidence of greater playing strength.
- Legal randomized openings provide controlled variety, not a balanced opening
  suite. Compare completed sample sizes, roles and actual search budgets; deadlines
  can vary across hardware even with identical seeds.
- Missing historical role/search evidence stays unavailable. Earlier records are
  not rewritten to invent the new diagnostics.
- Browser coverage uses Chromium desktop/phone emulation rather than physical
  devices. CUDA/MPS validation and target-host deployment remain operator work.
  Existing dependency/test warnings and Vite's bundle-size advisory remain
  separate from passing functional checks.
