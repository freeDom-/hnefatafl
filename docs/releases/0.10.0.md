# 0.10.0 — Reliable game setup and persistent identities

Selected AI models now display their correct names, complete game options return
next time, and training can continue through a reviewed checkpoint dialog.
Persistent runes and simpler naming/header controls make identities easier to follow.

### Fixed model selection and remembered options

- Selecting a model updates its display name with its model ID. Previously the
  selected weights could be correct while both sides still displayed the first
  recommended model's name. Ulf versus Freydis now keeps both IDs and names distinct.
- Older saved games use their recorded model-name snapshots in the two-sides
  panel, estimates and records. Their weights and historical JSON are not rewritten.
- Save the complete last successful setup: battlefield, game mode, human side and
  player choices, both agents and search settings, advisor, fixed-seed switch and
  seed. Restore it after closing/reopening the dialog or reloading the browser.
- Cancelled/failed creations leave saved choices intact. Corrupt data and removed
  or incompatible profiles/models fall back safely. Earlier mode-only preferences
  remain supported.

### Resume training from the workshop

- Resume from a job or a linked model card. Review the actual full checkpoint's
  completed iteration, battlefield, network and optimizer, then choose the target
  **total** iterations. The target must exceed the saved iteration.
- Continue the source job's latest `last.pt`, preserving optimizer, replay,
  random state, best snapshot and learning history. A retained best model card
  links to that source job's full checkpoint, rather than pretending an inference
  export contains training state.
- The server derives configuration from the validated checkpoint and starts a new
  job/output directory. Original outputs remain intact. Missing/corrupt/inference
  checkpoints and active jobs receive explanatory errors; no model-ID fallback or
  client-supplied filesystem path is used. English and German controls are included.

### Names, runes and a cleaner interface

- Tournament participants receive distinct editable Viking names by default.
  Reroll an individual name while keeping all agent/model settings. Manual names
  stay independent of profile/model changes.
- Model, tournament and tournament-player suggestions use the same **⚄** dice icon.
- Remove the header slogan and decorative overlines above page/panel headings.
  Keep language and appearance grouped at the top right, including mobile layouts.
  Statistical values retain their descriptive labels.
- Assign persistent unique runes to player UUIDs and model IDs. Reuse the same
  rune in setup, workshop, games, advisors, estimates and records. Names can repeat
  without losing identity; changing a model's search budget does not change its rune.
- Saved tournament seats have unique participant runes and separately show their
  underlying model/agent rune. Runes survive deletion and restart and are never
  recycled. After 24 single Elder Futhark runes, unique combinations extend the
  catalog without collisions. See [identity details](https://github.com/freeDom-/hnefatafl/blob/v0.10.0/docs/IDENTITIES.md).

### Validation

- **313 backend tests**, **74 frontend unit tests** and **26 real-API browser
  checks pass**. Four duplicate mobile worker checks remain intentionally skipped.
  Ruff/Prettier, mypy, TypeScript and the production build pass.
- Real CPU-trained Ulf/Freydis opponents retain distinct IDs, names and runes
  through creation, reload, setup, workshop and recorded games on desktop/mobile.
  Full saved options, including advisor and fixed seed, are restored.
- A real UI job resumes from one to two completed iterations with graph history
  retained. API tests compare resumed weights with uninterrupted CPU training and
  confirm the source checkpoint is unchanged.
- Rune tests cover concurrent allocation, more than 24 identities, deletion,
  legacy snapshots and consistent tournament/game agent identities. Compiled
  desktop/mobile views were inspected without page overflow or browser errors.
- Startup serves v0.10.0/schema 5 and preserves all seven existing game records
  exactly against a pre-upgrade digest. A complete backup was made first.

### Update and compatibility

Stop the service and back up the **complete data directory** before updating:

```sh
make install
make build
bash scripts/start.sh
```

Startup additively upgrades schema 4 to **schema 5** with an identity-rune table.
Existing gameplay JSON and model/checkpoint formats remain unchanged. Keep one
API worker. Older code does not understand schema 5; rollback requires the
pre-upgrade backup. Rune assignments belong to this installation's database.

Inference-only imports cannot exactly resume optimizer/replay state; retain the
source job's full checkpoint for resumption. CPU software validation does not
establish stronger models or validate CUDA/MPS hardware.
