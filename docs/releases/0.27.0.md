# MCTS node prediction reuse and traversal optimization

Phase 2 MCTS optimization: retain each node's prediction, reduce repeated search
work and preserve independent exploration. This is a stable feature release with
an annotated, unprefixed `0.27.0` tag. The existing remote-compatibility milestone
`0.26.0` was already tagged and published at baseline commit
`f9f68d26578920762aa46e7e408068c86febe30b`; it is not skipped or relabelled.

## Delivered behavior

- Each neural MCTS node receives its legal priors and defender-relative value once.
  Later expansion reuses that policy without another network/cache request. Every
  dependent simulation still waits for its value and completes a separate backup.
- Deferred leaf policies use owned uint16 action arrays and double probabilities;
  expanded nodes consume their own remaining-prior dictionaries. No dense logits,
  GPU tensors, cross-game search statistics or selected moves are retained.
- PUCT hoists the parent square root, scans edges in insertion order and preserves
  the reference arithmetic/first tie. Progressive widening uses an exact integer
  threshold with unchanged weighted sampling and random-number consumption.
- Existing cooperative batching, game replacement, ordered replay, root noise,
  terminal rules/history and heuristic rollouts remain independent. Cancellation
  is also checked during the root's tactical scan. Trees end with their move;
  managed training freezes weights until all searches finish.
- Additive MCTS request/reuse counters appear in JSON and the English/German
  workshop Performance view, separately from Phase 1 cache/deduplication counters.
- The existing benchmark supports validated read-only checkpoints, selected CPU/
  CUDA devices and sequential/batched/cache modes, explicit CUDA mixed precision,
  weights/checkpoint fingerprints, host metadata and process peak RSS. OpenVINO
  compiles/warms one frozen graph outside timing. Sequential CUDA self-play now
  passes its precision setting through the shared inference path too.

## Performance evidence

See [the reproducible Phase 2 measurements](../benchmarks/mcts-phase2.md) and
[performance/metric definitions](../PERFORMANCE.md#phase-2-retaining-mcts-predictions).
Three repetitions of each CPU case preserve completed work and trajectory hashes.
Brandubh batched throughput (simulations/s, before → after): 128/off **2178 → 2680**,
128/exact **2113 → 2301**, 256/off **2232 → 2759**, 256/exact **2005 → 2269**.
Tablut/192 improves **684 → 898** off and **689 → 804** exact; Copenhagen/256 improves
**400 → 522** off and **421 → 468** exact. Sequential/off and OpenVINO CPU improve;
sequential/exact is effectively unchanged (about 0.35% slower within sample ranges).

The rejected dictionary prototype increased traced tree memory 65–80%; packed
policies reduce that to 6.8–8.1% in the 256-simulation probe. The largest median
process RSS increase is 15.6 MiB/5.7%, a bounded host-memory tradeoff. No GPU
throughput or AI-strength improvement is asserted.

`make check` passed: documentation links, Ruff lint/format, mypy, frontend
Prettier/TypeScript, **1,058 backend tests passed with 6 hardware skips**, **191
frontend unit tests passed** and the production Vite build. The full suite includes
OpenVINO CPU conversion, cache-generation and actual optimizer/resume tests. A final
benchmark/CLI subset passed 21 tests after review. **19 relevant desktop/mobile
Chromium E2E checks passed**, with one intentional duplicate mobile training skip;
the real-server flow trained, resumed, loaded checkpoints and played legally.
Compatible remote-worker browser fixtures derive the running server version and
assert eligibility immediately, so a release version bump cannot silently turn
them into mismatch cases. Deliberate mismatch/override tests remain intact.

Coverage includes frozen Phase 1 tree statistics/RNG, node lifecycle,
PUCT ties, widening boundaries, repetition/royal tactics in all rulesets,
Copenhagen shieldwalls, deadlines/cancellation, cache generations, actual optimizer
updates, checkpoint reload/resume, remote workers and legal neural gameplay.

## Installation and update

Use the stable release's installer-compatible `hnefatafl-0.27.0.tar.gz` asset.
The release workflow requires successful Verify CI on the tagged main commit and
checks GitHub's SHA-256 asset metadata. See [deployment](../DEPLOYMENT.md).
No database, saved-game, replay, network architecture or checkpoint migration is
required. Update server and remote workers together: application versions must
match under the [existing compatibility policy](../REMOTE_TRAINING.md#application-compatibility-and-upgrades).

## Limitations and follow-up

Measurements use deterministic seeded weights because no existing checkpoint was
available. Short capped games measure computation, not completed-game strength.
CUDA, Apple MPS and Intel GPU hardware remain unverified; OpenVINO CPU is tested.
Packed leaf policies still add bounded host memory. CPU search/encoding and root
tactical engine work remain substantial. The scheduler and weighted widening
sampler were retained because profiling did not justify changing their semantics.

Phase 3 should separately evaluate training augmentation and mathematically valid
symmetry treatment with non-invariant models. It must not assume D4 equivalence of
existing neural predictions. Balanced strength evaluation and physical GPU runs
remain separate from this throughput work.
