# 0.23.0 - OpenVINO Intel GPU self-play inference

Optional OpenVINO Intel GPU inference for self-play training, with PyTorch CPU
optimization and portable checkpoints. The stable Git tag is **0.23.0**.

## Delivered behavior

- Explicit neural inference backend/device settings, separate from optimization.
  PyTorch remains the default; existing presets and training budgets are unchanged.
- Shared legal-policy inference, FP32 TorchScript conversion, bounded dynamic
  batches, one frozen model refresh per iteration, and resource cleanup.
- Crash-isolated capability probing, reported device names, compatible remote
  scheduling and named-worker validation without changing authentication or leases.
- Hardware-aware creation/resume controls, preserved explicit choices, backend and
  refresh timing in the dashboard, and older-history compatibility.
- PyTorch evaluation identities, paired budgets and champion promotion remain intact.
  Checkpoints still contain only validated tensors/primitives and can change backends
  on resume while preserving learning state.
- Repeated complete-iteration `benchmark-training`, including conversion/compilation,
  optimization, evaluation, persistence and actual inference-batch distributions.

## Validation

`make check` passed: 697 Python passes/five hardware skips in its full collection,
175 frontend passes, formatting/type checks, documentation and production build.
Final legacy transport and default inference regressions also passed. Browser
coverage: 56 distinct desktop/mobile passes (including the focused rerun of the
two new backend controls), four intentional duplicate mobile skips. Python 3.14.4
backend/benchmark checks passed 38 tests, with four explicit Intel GPU skips.
A separate environment without OpenVINO performed real CPU training and resumed
an OpenVINO-produced checkpoint with optimizer/replay intact. See the
[detailed validation record](../validation/openvino-2026-10-23.md).

Portable tests use OpenVINO
2026.4.1 on the Intel Xeon CPU plugin. No Intel GPU, CUDA or MPS hardware is present;
GPU acceleration and WSL2 deployment are unverified on this execution host.

FP32 parity covers Brandubh 32/2, Tablut 48/3 and Copenhagen 64/4; batches 1, 8, 16,
32 and varying sizes; legal/action ordering, terminal values, both sides, midgames,
normalization, determinism, saved weights and refresh after optimization.
Training tests exercise actual updates, checkpoint registration, resume with both
backends, cancellation and conversion failure. No new model-strength claim is made.

See [OpenVINO setup and benchmark interpretation](../OPENVINO.md).

## Installation and update

Use the production installer/updater with the published `hnefatafl-0.23.0.tar.gz`
asset and its GitHub SHA-256 digest, following [deployment](../DEPLOYMENT.md).
Automatic GitHub source archives are not production installation inputs.

For an Intel worker checkout, install the optional runtime in the same environment:

```sh
uv sync --frozen --extra train --extra openvino
.venv/bin/hnefatafl devices
```

Then explicitly select CPU optimization and OpenVINO GPU in the Workshop. Intel
GPU drivers/compute runtime are an OS prerequisite. Existing CPU/CUDA workers need
no OpenVINO extra and older reports continue to match ordinary jobs. No storage
migration is required.

## Limitations

No newly measured Intel GPU end-to-end speedup is claimed. Prior user-provided Iris
Xe forward-pass results are motivation only. Small batches/models and conversion
costs may lose performance. Evaluation uses PyTorch CPU. Native runtime failures
are isolated by process supervision; native conversion calls are not cooperatively
interruptible. TorchScript is deprecated in PyTorch 2.14 and requires parity
validation before a future conversion-route migration.
