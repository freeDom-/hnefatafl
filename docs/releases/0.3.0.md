# 0.3.0 - Search opponents and real self-play learning

All three rulesets now support headless computer play and an end-to-end workflow
for training, saving, importing and evaluating a neural opponent without writing Python.

### Added

- Tactical heuristic, iterative alpha-beta and Monte Carlo tree search, with bounded
  search budgets, rules-aware evaluation and seeded configurations.
- Neural policy/value search with legal-action masking and compatible model selection.
- Alternating-side tournaments with wins/losses/draws, per-ruleset results, game lengths
  and decision timings. Budget truncations are reported separately from rules draws.
- Actual PyTorch self-play optimization, CPU/CUDA/MPS device selection, CUDA mixed
  precision, replay buffers, configurable presets and JSON progress reporting.
- Exact CPU optimizer/replay/RNG resumption using `last.pt`; portable best-model
  preservation across weaker later iterations and output-directory changes.
- Compact inference exports, tensor-only checkpoint loading and validated model
  metadata, ruleset compatibility and architecture checks.
- Persistent Optuna studies, configurable search spaces, playing-score objectives,
  pruning and best-configuration export.

### Validation

- **86 AI, model and training tests passed**; lint, formatting and Python type checks passed.
- Baseline, alpha-beta, MCTS and trained opponents completed actual rule-terminal
  games in every ruleset; recorded moves replay to the reported outcomes.
- CPU smoke tests perform real weight updates, save/reload/register/import models,
  resume identically to uninterrupted training, and resume an optimization study.
- Documented smoke-training and two-trial optimization CLI commands ran successfully.

### Try it

```sh
uv sync --frozen --all-extras
.venv/bin/python -m hnefatafl.cli devices
.venv/bin/python -m hnefatafl.cli train --config configs/train-smoke.json
.venv/bin/python -m hnefatafl.cli tune --config configs/tune-smoke.json
```

See `docs/AI.md` and `docs/TRAINING.md` for full configuration, inference-model
import/export, exact checkpoint resumption and fair evaluation.

### Limitations

- This milestone delivers the CLI and Python interfaces. Browser gameplay and job
  management arrive in the next application milestone.
- CUDA/MPS execution has not been verified on this CPU-only host. CPU wheels do not
  provide CUDA; install an appropriate official CUDA build on GPU hardware.
- Small smoke runs prove the software pipeline, not improved playing strength.
  One executed sample lost both evaluation games; larger balanced evaluations are needed.
- Copenhagen's primary-source verification limitation remains documented.
