# 0.4.0 - Playable browser application and training workshop

The headless engines, opponents and learning tools are now integrated into a
responsive application for local human games, computer play, saved histories,
statistics and web-managed training.

### Added

- React/TypeScript interface with a parchment-and-pine Viking board, touch/mouse/
  keyboard interaction and responsive desktop/mobile layouts.
- Tablut, Brandubh and Copenhagen in Human vs Human, Human vs AI and AI vs AI modes;
  legal move highlighting, captures, active turn, history, game-over messages,
  undo/redo, new games and restart without deleting the previous session.
- Configurable AI profiles/models, playback speed, pause/resume and thinking status.
- FastAPI server-authoritative moves, optimistic version checks and transactional
  SQLite persistence, stable local identities and deterministic saved-game replay.
- Filtered statistics with completed-game denominators, W/L/D percentages, side
  rates and distinct AI/model labels. Viewing replay no longer changes recorded results.
- Training dashboard for presets and advanced settings, device information,
  actual progress/evaluation/logs, cancellation and full-checkpoint/study resumption.
- Safe model import/export and side-by-side evaluation summaries. Invalid metadata
  is rejected before it can break the interface.
- Independent worker lifecycle with graceful stop/checkpointing, actual process-exit
  tracking, overlap prevention and cleanup on API shutdown.
- Locked installation, production/development launch scripts, systemd/proxy examples,
  complete documentation, actual screenshots and Python/browser GitHub Actions.

### Validation

- **173 Python tests passed**, **5 Vitest tests passed**, and **5 real-API Playwright
  checks passed**. One redundant mobile training check is intentionally skipped;
  mobile gameplay runs and actual CPU training runs on desktop.
- Desktop/mobile browser flows complete a real AI game, verify game-over controls,
  retain the archive result and reopen the completed session.
- Browser training performs self-play and updates, registers the model, selects it
  as an opponent and makes a legal neural move.
- Ruff/Prettier, mypy/TypeScript and the production build pass.
- Production startup serves the compiled app; real requests create, move and reload
  games in every ruleset. Locked installation/build and startup were repeated successfully.

### Install or update

```sh
make install
make build
bash scripts/start.sh
```

The service binds loopback on port 8000 by default. For trusted LAN phone access,
set `HNEFATAFL_HOST=0.0.0.0`. Back up the data directory before updating. The initial
SQLite schema remains version 1; there is no destructive schema migration.

### Limitations and next validation

- This is a feature preview (`v0.x`), with CPU verification. CUDA/MPS needs compatible
  hardware and the official matching PyTorch distribution; no GPU result is claimed.
- Copenhagen's primary page remains unavailable (HTTP 455). Its exact documented
  transcription interpretation and finite repetition convention need reconciliation
  when the primary source is accessible.
- Local profiles are not authenticated internet accounts. Public deployment requires
  an authenticated TLS reverse proxy; target-host systemd/LXC operation is unverified.
- Mobile checks use Chromium emulation. Physical devices and other browser engines
  need additional compatibility testing. Full offline and internet multiplayer are later work.
- Functional smoke training is not evidence of strength. Longer balanced experiments
  and GPU throughput measurements remain separate work.
