# 0.24.0 - D4 symmetry foundations and exact-input inference reuse

D4 symmetry foundations and optional exact-input inference reuse. The stable tag
is **0.24.0**. Caching defaults off; saved games and tensor-format-1 checkpoints
remain compatible.

## Delivered behavior

- Pure-Python D4 coordinates, moves, boards, states, full repetition histories,
  inverses, deterministic canonical boards and separate full-history state keys.
  No engine, search, replay or neural behavior uses symmetry canonicalization yet.
- Optional bounded LRU for identical ruleset/board/turn neural inputs and pending
  batch deduplication, shared by sequential and batched self-play. Symmetric
  orientations remain distinct. Terminal adjudication and per-search RNG/noise,
  trees, legal support, targets and simulation budgets are preserved.
- One cache per self-play generation, explicit backend generation invalidation,
  tensor version guards, compact immutable host policies and independent returned
  dictionaries. No GPU tensors, dense logits or root noise are retained.
- Validated `inference_cache_mode` (`off` or `exact`) and
  `inference_cache_capacity` (4096 default, 1–65536) in CLI, training, jobs, creation
  and resume controls. Current remote workers advertise cache support; older
  workers retain default-job compatibility through filtered transport copies.
- Additive logical-request, actual-evaluation, lookup, hit/miss, batch-duplicate,
  occupancy and timing metrics in existing JSON/dashboard performance output.
- Repeated cache-off/exact self-play benchmarks, seeded trajectory checks and
  controlled duplicate-heavy/unique-input inference workloads.

## Validation

`make check` passed: **963 Python tests**, six hardware skips, **176 frontend
unit tests**, lint/format, both type checks, documentation and production build.
`make docs` also passed separately. **56 distinct real-server desktop/mobile
browser checks** passed, including the focused rerun after correcting cache form
locators and the duplicate capacity control; four redundant mobile checks are
intentionally skipped. Final cache/backend-generation and benchmark tests passed
34 tests with one CUDA skip; resume/cache frontend regression checks passed 21.

Pure D4 tests cover every ruleset, all eight transforms, seeded legal histories,
recorded repetitions, king escape/capture, shieldwalls, encirclement and edge forts.
Real model tests cover ordering, exact/history-safe reuse, independent root noise,
LRU eviction, weight/backend/precision changes, cancellation, actual optimizer
updates and checkpoint resume. OpenVINO 2026.4.1 CPU integration runs real inference,
conversion parity, snapshot refresh and training/resume. CUDA and Intel GPU
performance require matching hardware. These checks establish functional
correctness and compatibility, not model strength.

## Performance evidence

Five-repetition CPU comparisons use seed 17, two math threads, eight games,
concurrency/batch limit eight and FP32. Small models use four channels/no residual
blocks, eight MCTS visits and twelve plies. A 32-channel/two-block Brandubh network
uses sixteen visits/sixteen plies. All cache pairs compare identical weights and
matching actual simulation counts (including unchanged winning-root shortcuts)
and no deadline cutoffs. Speedup is off median / exact median; below 1× means
a regression.

The [raw report](../benchmarks/exact-input-cpu-2026-10-24.json) retains all 80
self-play runs and controlled duplicate/unique-input workloads, including CPU time,

Caching is reversible and remains off by default. Fewer network evaluations do
not imply faster generation, complete training or better models. Python search,
lookup/policy-copy overhead and smaller effective batches can dominate. No CUDA,
MPS or Intel GPU improvement is claimed.

## Installation and update

Use the production updater/installer with published `hnefatafl-0.24.0.tar.gz` and
its verified GitHub SHA-256 digest; follow [deployment](../DEPLOYMENT.md).
Automatic GitHub source archives are not production installation inputs.
For an existing source checkout, update to the tag, install locked dependencies
with `make install`, rebuild with `make build`, and restart the server/workers.
OpenVINO workers additionally install `uv sync --frozen --extra train --extra openvino`.
Back up retained data before upgrading. No storage or checkpoint migration is
required. Old configurations default off. Upgrade workers to 0.24.0 before using
exact mode; off jobs remain compatible with older workers.

## Limitations and Phase 2

Caches are scoped to inference generations and are not global or persistent.
External low-level `.data` writes bypassing tensor version counters require an
explicit cache clear; managed training replaces caches before optimization.
Capacity bounds entries rather than host bytes; tune it conservatively on large
boards. Numeric kernel rounding may differ after batch deduplication; tested FP32
tolerances and seeded behavior are documented. TorchScript deprecation and native
OpenVINO cancellation limitations from 0.23.0 remain.

Phase 2 should measure representative GPU/complete-training budgets before
changing defaults. Symmetry augmentation, canonical neural inference, replay
merging, symmetry pruning, transposition changes and MCTS subtree sharing are
future work. Existing model predictions are not assumed D4 invariant, and no
eightfold speedup is promised.
