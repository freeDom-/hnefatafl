# 0.9.0 - Agent insight, bilingual play and a northern workshop

Inspect what each AI thinks about the position, get optional move advice, and
train with clearer progress, board-specific plans and retained best models.
English and German interfaces and a timber-hall appearance complete the update.

### Agent evaluations and legal-move advice

- New ordinary games retain independent position assessments from each playing
  AI. Both agents estimate the prospects of the **same current player**, making
  their disagreements visible during play and recorded replay.
- Reports identify heuristic, MCTS-rollout, neural-value or exact-outcome sources
  and retain configuration/search diagnostics. They survive reload and completed
  model deletion. Missing historical reports remain explicitly unavailable.
- A **Move advisor** dropdown in New game offers compatible profiles and trained
  models, with **None** selected by default. Its best searched legal move appears
  as an arrow and source/target highlights; it never executes the player's move.
- Estimates are expected-score values: draws count as half. They are **not
  calibrated winning probabilities** or evidence that an agent is stronger.
  See [analysis details](https://github.com/freeDom-/hnefatafl/blob/v0.9.0/docs/ANALYSIS.md).

### Setup, records and model selection

- Remember the last successfully created game mode across dialogs and reloads.
- Open Player & AI performance with **W / D / L descending**, most wins first.
- Combine otherwise equal AI configurations across random seeds. Individual game
  seeds remain recorded; different model IDs and other search parameters still
  distinguish agents. Aggregate parameter dialogs explain the seed grouping.
- Tournament opponents preselect the strongest compatible model using the same
  saved evaluation evidence and fallback rules as New game. Manual choices remain.
- Model dropdowns in both forms show actual iteration, planned total when known,
  network width/depth and short ID, distinguishing models with the same name.
- Suggest editable northern-mythology tournament names with a reroll button and
  duplicate avoidance. German suggestions follow the selected interface language.

- The [training plan](https://github.com/freeDom-/hnefatafl/blob/v0.9.0/docs/TRAINING_PLAN.md)
  explains input features, receptive fields, policy/value learning, replay,
  exploration, learning rates and a controlled comparison process. These are

  Full recommended runs can take hours or days; Smoke is a short software check.

  offer an accessible data table and retain history through reopening/resumption.
- Optional **Save every new best model** preserves and immediately registers each
  strict baseline-score improvement. Ties create no extra retained snapshots.
  Existing final-best and resumable checkpoints remain available. This option
  uses additional storage and is off by default.

### Validation

- **302 Python tests**, **67 frontend unit tests** and **24 real-API browser
  checks pass**. Four duplicate mobile worker checks are intentionally skipped.
  Ruff/Prettier, mypy, TypeScript and the production build pass.
- Analysis cases cover provenance, current-player perspective, legal hints,
  immutable replay, stale results, branch isolation, missing models, advisor

- Real CPU training produced three history points and two retained best

- Compiled desktop/mobile views were inspected with no page overflow or browser
  errors. Production startup serves v0.9.0/schema 4 and preserves all seven
  existing game records exactly against a pre-upgrade digest.

### Update and compatibility

Stop the service and back up the **complete data directory** before updating:

```sh
make install
make build
bash scripts/start.sh
```

Startup additively upgrades schema 3 to **schema 4**, adding per-position analysis
without rewriting game JSON. Older games have no invented historical evaluations.
Keep one API worker. Rollback requires the pre-upgrade backup because older code
does not understand schema 4. Checkpoints and model formats remain compatible.

Position assessments belong to ordinary game histories; tournament replay keeps
its existing match/outcome records. Search remains budget-limited. CUDA/MPS,
physical mobile devices and long strength comparisons require separate validation.
