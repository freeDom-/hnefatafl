# Personal tables and inspectable opponent records

Players can now customize the table, manage model/player collections and compare
AI configurations without losing recorded history.

### Added

- Model deletion from AI workshop cards, with confirmation and immediate selection
  refresh. Original training checkpoints, completed histories and model labels remain.
- Human-player deletion from the Hall of records, preserving stable historical
  identities, names, results and replay while hiding profiles from future selection.
- One clear human-player dropdown per side, with existing profiles and a new-player
  option that correctly clears a previously selected ID.
- Separate AI records keyed by normalized effective settings, including relevant
  algorithm budgets, depth, exploration, temperature, seed, evaluation and model.
- Expandable AI parameters and compact summaries in both recorded games and
  performance rows. Legacy omitted defaults retain their original meaning.
- Viking-inspired model-name suggestions that avoid existing/current names.
- Consistent 7×7, 9×9, 11×11 battlefield order in new games, records and training.
- Persistent Light, Dark and Follow device appearance modes, with live previews.
- Independent token themes: Classic stones, illustrated Viking shield bearers and
  crowned king, and weathered carved wooden pieces.
- Independent board themes: Golden oak, Old walnut and Fjord slate. Typed catalogs
  and shared renderers support adding more sets without changing rules.

### Integrity and behavior

- Model deletion blocks unfinished games that still need its weights. Completed
  games remain replayable; deleted weights cannot generate a new continuation.
- A deleted human name can be reused by a new profile with a new ID. Old history
  stays attached to the original identity. Restarting a retired setup asks for active
  players/models in a new game instead of silently reviving them.
- Catalog changes serialize with new game creation; registry deletion is locked,
  atomic and preserves original job files. Historical model metadata is retained.
- Appearance choices are browser-local and independent of game/AI parameters.
  Invalid preferences fall back safely; blocked storage permits visit-only settings.

### Validation

- **196 Python tests**, **14 frontend unit tests**, and **10 real-API browser checks
  passed**. Two redundant mobile training checks are deliberately skipped; actual
  training/model deletion runs on desktop, and mobile gameplay/records/themes run.
- Regression coverage includes deletion/new-game races, schema migration/repeated
  startup, retained legal replay, legacy model names, normalized parameter variants,
  dropdown identity clearing, confirmation cancel/error paths and name collisions.
- Browser checks verify actual figure artwork and board colors, persisted choices,
  device color-scheme changes, a legal move after theming, and mobile overflow.
- Ruff/Prettier, mypy/TypeScript and the production build pass.
- Test collection isolates default application storage; production restart preserves
  existing game records exactly and serves the new compiled interface.

### Update and migration

Stop the service and back up the whole data directory before updating. Startup
automatically upgrades SQLite schema 1 to 2 by adding player tombstones and a
metadata-only model-history table; existing game records and checkpoint files remain.
The upgrade is repeatable. Restore a consistent pre-upgrade backup if rolling back
to code that does not understand deleted-player tombstones.

```sh
make install
make build
bash scripts/start.sh
```

Use **Appearance** in the header for themes, **Hall of records** for profiles and
opponent settings, and **AI workshop** for suggested names and model deletion.
See `docs/PERSONALIZATION.md` for screenshots and theme extension points.
