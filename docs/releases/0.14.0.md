# 0.14.0 — Battlefield opponent win matrices

Tournament battlefield results now show a table with every opponent on both
axes. Each cell counts the row opponent's wins over the column opponent; the
diagonal displays that opponent's persistent rune.

### Results at a glance

- Include every configured seat in its original order, with numbered names to
  distinguish repeated models/profiles.
- Count saved wins separately for each battlefield, regardless of which side the
  opponent played. Exclude draws and unfinished games.
- Update from saved matches during a running tournament and retain the same view
  after stopping, reloading or reopening it. Unplayed pairings show zero.
- Keep existing battlefield totals and match replay. Earlier two-player records
  remain compatible through their original side-assignment convention.
- Provide English/German labels, row/column headers, and keyboard-accessible
  horizontal scrolling with fixed row headers on narrow screens.

### Validation

**369 backend cases**, **107 frontend unit tests** and **seven targeted
desktop/mobile tournament browser checks** pass. One duplicate mobile cancellation
check is intentionally skipped. Formatting, type checks and the production build
pass.

Focused cases cover directional wins, both side assignments, independent
battlefields, draws/unfinished games, partial results, repeated names/runes and
legacy two-player records. Real-API desktop/mobile flows play a four-opponent
tournament on two battlefields, compare every cell with saved outcomes and verify
the matrix again after reload. No tournament scoring or stored records change.

See [validation evidence](https://github.com/freeDom-/hnefatafl/blob/v0.14.0/docs/VALIDATION.md).

### Update and compatibility

```sh
make install
make build
bash scripts/start.sh
```

Back up the complete data directory and stop the server before updating as usual.
Storage remains **schema 6**. No database, checkpoint or tournament migration is
required; the browser derives the matrix from retained match records. The table
shows observed win counts, not calibrated winning probabilities or a claim of
model strength.
