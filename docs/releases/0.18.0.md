# 0.18.0 — Portable training jobs

Saved training runs can move between installations through **Export job** and
**Import job** in the AI Workshop. Import opens the new job with its configuration,
history, graphs, evaluation and performance metrics, and restores its playable
models. Full checkpoints continue through the existing reviewed Resume workflow.
The resume dialog preserves effective checkpoint settings and no longer offers a
preset selector; new training retains its preset selection.

### Delivered behavior

- Versioned ZIP inventory with source application/job identity, file sizes and
  SHA-256 checksums; available JSON, logs, full/best/inference checkpoints, retained
  best snapshots and associated registered inference models.
- Fresh job IDs, destination path/model-reference rebasing, preserved timestamps
  and local/remote provenance, inactive local restoration and model deduplication.
- Bounded staged validation using the existing tensor-only loader. Unsafe paths,
  symlinks, conflicting entries, invalid metadata/checksums and incompatible
  checkpoints fail with API errors. Controlled publication failures roll back new
  files, SQLite rows and catalog entries while preserving existing data.
- Single contained Optuna SQLite studies, including trial directories/results,
  study history and checkpoint references, can migrate and use **Resume study**.
- English/German controls, import/export loading and errors, model/list refresh and
  direct selection of the imported job.

### Validation

`make check` passes: **527 backend tests**, **143 frontend unit tests**, local
Markdown links, Ruff lint/format, mypy, TypeScript, Prettier and the production
build. One CUDA inference test is skipped because this host has no compatible GPU.
The final **49 migration tests** also pass after the last hardening changes.

Two focused Playwright cases pass against the actual server on desktop Chromium
and a mobile Chromium viewport: train on CPU, download the ZIP, import/select the
job, verify model deduplication and resume through the preset-free dialog. The
full browser suite was not run locally; milestone CI runs the repository suite.

The isolated CPU round trip preserves history, metrics and timestamps, safely
handles an existing source ID, resumes a full imported checkpoint to iteration 2
with increased optimizer steps and changed weights, leaves its source unchanged,
and selects a legal move with its restored inference model. A real one-trial
Optuna study migrates and completes a further trial through Resume study.

Coverage includes native/already-imported model deduplication, retained snapshots,
remote inference copies without a final worker report, missing optional models,
re-export, concurrent imports, corrupt/incompatible archives, traversal/symlink/
duplicate entries, upload/extraction/ratio bounds and publication rollback. Study
checks reject external/missing checkpoints, active trials, multiple studies and
unsupported/executable schemas; sanitization also removes old credentials/paths
from SQLite free pages.

CUDA/MPS training and cross-device numerical reproducibility were not tested.
A CUDA-configured tensor fixture loads on this CPU host, but no real CUDA-created
training fixture was available. Small CPU runs establish functional learning and
migration, not playing strength. The existing Vite bundle-size advisory remains.

### Installation, update and migration limits

Stop training/server processes and back up the full data directory before updating:

```sh
make install
make build
bash scripts/start.sh
```

Database schema 7, neural architecture and tensor checkpoint formats are unchanged.
Job archive format 1 requires compatible destination training settings/checkpoints;
Optuna migration supports schema 12 and one inactive, job-owned SQLite study.
No automatic training, worker enrollment, credential transfer or foreign execution
ownership is restored. Choose CPU/Automatic when resuming a CUDA-configured job on
a CPU-only destination. Hardware-dependent numerical determinism is not guaranteed.

Active jobs, active study trials, shared/external study databases, incomplete trial
dependencies, multiple studies in one database and unknown study/archive schemas
are rejected. A resumed study whose outputs span other job folders needs a full
backup. Remote archives include only artifacts already uploaded to the server.
Optional missing artifacts stay unavailable; inference-only weights remain playable
without full-state resumption. Limits: 512 MiB ZIP, 1 GiB extracted, 2,048 files,
128 MiB per artifact, 16 MiB per JSON and 200:1 decompression. Exports store entries
without compression. Custom diagnostic text should be reviewed before sharing.

See [Training data and migration](../TRAINING_DATA.md#moving-data-between-installations)
for the workflow and the distinction between importing models and jobs. Copying a
folder into `data/jobs/` alone still does not register its SQLite job row.
