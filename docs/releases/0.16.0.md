# 0.16.0 - Editable training resumption and neural search wrappers

Resume training with reviewed parameter changes while retaining the saved learning
state. Trained models can now use MCTS, alpha-beta or direct policy move selection
in games, tournaments and position analysis.

### Editable training resumption

- Show all new-training configuration fields in the Resume training dialog,
  initialized from the saved configuration. Keep ruleset, network channels,
  residual blocks, random seed and optimizer type read-only.
- Edit self-play, batch, epoch, MCTS, evaluation, checkpoint, device and mixed
  precision settings, alongside model name and retained-best-model preferences.
  Selecting a preset changes its editable budgets while preserving the five
  immutable checkpoint settings.
- Keep iterations as the target total count, strictly greater than the number
  already completed. Apply the same bounds and validation used for new jobs.
- Restore weights, optimizer buffers, replay, random-generator state, history and
  best-model tracking. Apply reviewed learning-rate, weight-decay and SGD momentum
  changes after optimizer-state loading so restored parameter groups do not
  overwrite them. Adam/AdamW keep their accumulated moments.
- Return effective saved configuration through the resume API and accept editable
  overrides for local or remote execution. Older checkpoint metadata can use the
  source job's saved inputs for missing fields; source checkpoints remain unchanged.

### Search wrappers for trained models

- Add **Search wrapper** to the trained-model controls in New Game and Tournament
  setup. Show only the selected wrapper's relevant controls while retaining hidden
  search values when switching wrappers.
- **MCTS** keeps the existing policy-prior and value-head tree search, with
  iterations, exploration, temperature and time limit controls.
- **Alpha-beta** reuses the existing search and evaluates nonterminal leaves with
  the model's value head. Depth and time limit remain configurable.
- **None (policy only)** selects the highest-probability legal move directly from
  the model by default. Positive temperature enables seeded policy sampling,
  without tree search or rollouts.
- Persist the backend `search_wrapper` setting with values `mcts`, `alpha_beta`
  or `none`. Missing settings retain **MCTS**, including existing saved games,
  tournaments and model configurations. Non-neural opponents keep their behavior.
- Use the selected wrapper for actual play, tournaments and position analysis,
  retaining model compatibility checks, legal-move masking and seeded decisions.

### Validation

**90 targeted backend tests** and **68 frontend unit tests** pass, together with
Ruff lint/format checks, mypy, TypeScript, Prettier and the production build.

Focused checks cover parameter overrides, immutable settings, optimizer-buffer
preservation, exact CPU resumption, replay/history/best-model retention, remote
resume compatibility, model loading, legal neural moves, all wrapper modes,
default-MCTS compatibility and New Game/Tournament configuration handling.

### Install, update and compatibility

Stop the server and back up the complete data directory before updating:

```sh
make install
make build
bash scripts/start.sh
```

Storage remains **schema 7** and the existing checkpoint/model format is unchanged.
No data migration or model conversion is required. Existing jobs and configurations
remain compatible, and the five immutable settings retain their checkpoint values.

Validation used CPU execution and short real training/resumption checks. CUDA/MPS,
long training runs and independent playing-strength comparisons were not tested.
The full browser end-to-end suite was not rerun locally for this milestone. Search budgets
can stop before the requested depth or simulation count completes; passing smoke
tests does not establish a stronger model or calibrated winning probabilities.
