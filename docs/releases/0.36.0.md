# 0.36.0 - Reliable tuning, online learning-rate adaptation and model reuse

This stable milestone brings selectable tuning opponents and checkpoint-based
studies, optional online learning-rate adaptation, inference-weight model
reuse, and clearer training analysis. It includes every change merged to `main`
since the published `0.35.0` release: PRs
[#52](https://github.com/freeDom-/hnefatafl/pull/52),
[#53](https://github.com/freeDom-/hnefatafl/pull/53),
[#54](https://github.com/freeDom-/hnefatafl/pull/54) and
[#55](https://github.com/freeDom-/hnefatafl/pull/55).

Database schema remains **13** and checkpoint tensor format remains **1**.
Update remote workers to **0.36.0** before assigning new work. Existing tuning
studies with ambiguous historical identities remain readable/exportable, but
require a new study for further trials; new job archives use **format 2** with
backward import support for format 1.

Full comparison: [`0.35.0...0.36.0`](https://github.com/freeDom-/hnefatafl/compare/0.35.0...0.36.0).

## Training and AI changes

### Selectable opponents and reliable tuning (#52)

- Tune against Shield bearer, Shield maiden or Jarl, or use a normalized weighted
  objective across fixed references and frozen registered neural models. Champion
  is rejected because a changing opponent would make trials incomparable. Frozen
  opponents may use different network widths/depths while sharing the ruleset;
  sequential, batched and supported parallel MCTS evaluation keep their inference
  models separate. Weighted evaluation adds games to the trial budget.
- **Tune this checkpoint** starts each trial from a validated source checkpoint
  with an explicit additional-iteration budget. Source weights, optimizer state,
  replay, RNG and history are preserved, and the source is never overwritten.
  Checkpoint trials cannot tune architecture fields fixed by that source.
- Trials now optimize their **best newly evaluated candidate**, even when it
  scores below an inherited benchmark. `objective.pt` retains that candidate's
  full training state; `last.pt` retains the final state and `best.pt` the overall
  selected best. Trials no longer populate the permanent playable-model registry.
- Applying winning parameters opens the normal Resume Training dialog with
  differences highlighted against the effective checkpoint configuration.
  Explicit learning-rate and weight-decay changes take effect while restored
  optimizer moments/buffers are kept. Continue the winning full checkpoint, start
  a fresh job with its parameters, or download its full configuration. The winning
  candidate or final trial state can also become a subsequent tuning source.
- Optional held-out verification uses an independent seed after optimization
  results and winning references are saved. Verification failure or cancellation
  leaves completed trials and winning parameters usable. A study with no winner
  skips verification and preserves its failure diagnostics.
- Version-2 experiment identities bind source content, fixed workload, evaluation
  protocols, frozen opponents, seeds, search space, runtime and sampler/pruner
  settings. Conflicting resumptions are rejected before launching trials;
  additional trial and failure budgets remain editable. Local SQLite leases
  prevent simultaneous study invocations, and failed trials remain visible rather
  than leaving a study stuck running. Sampler/pruner configuration and validated
  float, integer and categorical search distributions are supported.

See [tuning](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/TRAINING.md#hyperparameter-optimization).

### Optional online learning-rate adaptation (#53)

- Set `adaptation: "hypercontroller"` to adapt the learning rate inside one
  continuing self-play job. It is **off by default**, changes only existing
  optimizer parameter groups, and preserves momentum and optimizer identity.
  Optuna tuning and online adaptation are mutually exclusive.
- Choose 2–8 distinct `adaptation_lr_candidates` between `1e-7` and `1`, including
  the starting `learning_rate`. Cadence, warm-up, minimum dwell, history lag and
  per-context exploration budgets are configurable. Invalid enabled inputs are
  rejected; inactive fields are sanitized without blocking ordinary training.
- Decisions occur after existing evaluations against one fixed, non-Champion
  opponent, with at least four games configured. The signal is
  `(wins + 0.5 * draws) / completed_games`; unfinished games are excluded, and no
  extra evaluation is added. Missing/non-finite observations do not advance the
  controller. Warm-up, exploration, dwell and fallback bound decision behavior.
- Full checkpoints preserve bounded controller state and its dedicated random
  stream. An unchanged resume keeps the selected rate; an explicit rate override
  takes effect. Changed candidates, history window or evaluation settings reset
  learned controller state with a visible reason. Malformed state resets only the
  controller, preserving model, optimizer and training history. Older checkpoints
  without controller state remain usable.
- Creation/resume forms include English/German controls and parameter help.
  Monitoring shows the effective rate, decisions and reset reasons; history
  distinguishes the rate **Used** in an iteration from the rate **Selected** for
  the next interval. Candidate parsing is bounded and preserves distinct accepted
  floating-point values through configuration round-trips.

The documented three-seed, four-iteration CPU Brandubh smoke benchmark reports
median controller time **0.31 ms per run**, about **0.08 ms per decision**. This is
controller overhead evidence only: it establishes neither faster training nor
stronger play, and held-out strength testing was not executed. The comparison's
step scheduler is a benchmark built with resume, not a new training setting.
See [the measured protocol and limits](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/benchmarks/online-hyperparameter-adaptation.md)
and [adaptation configuration](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/TRAINING.md#automatic-hyperparameter-updates).

## Model and training-data fixes

### Reuse identical inference weights (#54)

- Completing a run without a new best model, resuming identical training, or
  importing equivalent weights now reuses a verified catalog model instead of
  creating duplicate entries and persistent checkpoint copies. Identity covers
  architecture and inference tensors, excluding optimizer state, timestamps and
  other metadata. Jobs report whether a model was reused and whether a new best
  was produced; multiple jobs may reference the same model.
- Existing IDs, names, runes and references remain stable. Legacy fingerprints are
  backfilled lazily after the original content-addressed identity is verified.
  A recorded weight identity cannot silently change if its owned file is replaced;
  inconsistent weights/rulesets produce a diagnostic. Healthy matching entries
  are preferred over damaged duplicates.
- Re-importing a matching model can repair a missing/corrupted owned copy outside
  an archive transaction. Archive imports verify identity through the same
  registry, remap all model references consistently and roll back new registrations
  on failure; they never repair existing copies as a side effect.
- `hnefatafl models --registry data/models --duplicates` provides read-only
  duplicate detection. Existing duplicates are **not deleted automatically**.
  Full training checkpoints and job-local `inference.pt` remain available for
  resume, remote upload and archives.

See [model management and cleanup](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/TRAINING_DATA.md#detecting-and-cleaning-up-existing-duplicates).

### Portable studies and recoverable whole-study deletion (#52)

- Format-2 tuning archives include the shared SQLite study, all contributing trial
  artifacts, source dependencies and verified frozen opponents. Exporting an
  earlier member includes the current winner/history. Import preserves scores and
  trial numbers, rebases references and verifies paths, ownership, checksums,
  supported schema and frozen-model content. Format-1 imports remain supported
  when required dependencies are verifiable; existing archive quotas still apply.
- Retained studies protect source checkpoints, database owners, contributors and
  selected/winning trial artifacts after completion, failure or cancellation.
  Missing or changed frozen opponents block transfer/further trials instead of
  silently changing the experiment.
- Administrators can preview and explicitly confirm **Delete entire tuning
  study** from any inactive member. It removes the study's participating jobs and
  directories while keeping source jobs, registered models, games and tournaments.
  External retained dependencies, active jobs/processes, unfinished remote leases
  and held study leases block deletion; there is no force/cascade option.
- Whole-study deletion revalidates its preview, stages directories on the same
  filesystem and records a durable recovery journal. Startup restores pre-commit
  removals or finishes committed cleanup. Pending cleanup is reported; ambiguous
  recovery fails closed instead of exposing partially restored training data.

See [job management](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/TRAINING_DATA.md#managing-models-and-retained-training-data)
and [study archives](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/TRAINING_DATA.md#optimization-studies-and-archive-limits).

## UI and usability improvements

- Tuning results distinguish inherited benchmark, candidate objective, final and
  aggregate scores. Objective-based sorting/winner selection, trial-history and
  parameter charts, exploratory importance and 50-row pagination make studies
  easier to inspect. Navigator polls omit full trial histories while selected-job
  details retain results. Opponent-weight help remains keyboard-accessible when an
  input is disabled. New tuning, deletion and adaptation flows include German
  translations (#52, #53).
- Learning, Evaluation and Performance share **100** and **250** iteration windows
  alongside All, 10, 25 and 50. Windows follow actual iteration numbers, including
  resumed/sparse histories. Learning charts, replay data and adaptation decisions
  use the same latest-training-iteration anchor; All restores the complete log
  (#55).
- Dense evaluation charts thin redundant markers while preserving segment ends,
  gaps, isolated points and promotion indicators. Small series/scatter plots,
  exact tables and keyboard/pointer inspection keep all observations available.
  Learning charts reuse the already-windowed history instead of repeatedly
  normalizing/sorting the full history. No numerical speedup is claimed (#55).

## Infrastructure and compatibility

- Workers advertise `hyper_adaptation`. Enabled adaptation requires that
  capability even with an administrator version override; legacy transports omit
  unsupported adaptation fields. Worker-selection errors now identify the missing
  capability. Update server and workers together to satisfy exact-version matching.
- The training API accepts the new tuning/adaptation controls and portable source
  checkpoint tokens. Administrator-only study deletion adds preview and confirmed
  deletion endpoints with permission documentation. No existing runtime key is
  removed or renamed.
- Training, dashboard, data-management, remote-worker and architecture guides now
  document the delivered behavior. Browser smoke-training fixtures isolate weights
  between projects. Publication uses the checked-in notes verbatim and names the
  GitHub release `Hnefatafl 0.36.0`; archive packaging and CI/digest gates remain.

## Upgrade and installation

1. Stop/cancel training and tournaments, pause remote claim loops and stop unmanaged
   CLI writers. Take a complete stopped-writer backup of the data root and protected
   configuration, retaining matching `0.35.0` code.
2. Once the stable release and verified source archive are published:

   ```sh
   hnefatafl-update --check
   hnefatafl-backup
   hnefatafl-update --version 0.36.0
   ```

   On Proxmox, prefix these commands with `pct exec <CTID> --`. Fresh installations
   follow [Deployment](https://github.com/freeDom-/hnefatafl/blob/0.36.0/docs/DEPLOYMENT.md).
   Use the attached `hnefatafl-0.36.0.tar.gz`, not GitHub's automatic source archive.
3. Confirm application readiness and schema **13**. There is no database migration
   or checkpoint tensor-format change. New optional controller/registry metadata
   does not rewrite source checkpoints or historical model IDs.
4. Update remote workers to **0.36.0** before resuming assignments. Adaptation
   additionally requires `hyper_adaptation`; it stays off unless explicitly enabled.
5. Start a **new study** when an old study lacks a complete comparable version-2
   identity; historical results remain inspectable/exportable. Further trials in a
   current study must retain its fixed workload, source and evaluation identity.
   Keep frozen dependencies available for study transfer/resumption.
6. Format-2 archives require a destination that understands the format and included
   configuration. Do not assume older releases can import them or continue new
   study semantics. Keep the full pre-upgrade backup for rollback rather than
   relying on reverse migration or dropping new state.

## Limitations

- Online adaptation optimizes a noisy fixed-opponent proxy, not Elo or held-out
  playing strength. There is no rollback of optimizer updates already applied.
  This release claims no stronger pretrained model or benchmarked GPU speedup.
- Whole-study deletion coordinates filesystem and SQLite recovery; it is not one
  atomic transaction across both. Keep the single API-worker deployment and stop
  unmanaged CLI writers for administrative cleanup. Preserve recovery journals
  with their quarantined directories; unsafe states require repair.
- Inactive studies do not indefinitely reserve frozen registry models. Missing or
  unverifiable dependencies block transfer/resumption until restored or replaced
  by a new study. Remote Optuna execution remains unsupported.
- First import after upgrade may load legacy catalog checkpoints once on CPU to
  backfill fingerprints. Historical duplicate cleanup is an explicit operator task.
- Numeric windows can contain fewer observations than their size when histories
  are sparse. Cadence-separated evaluation points retain their gap markers.
- Local CPU/Chromium evidence does not establish CUDA, MPS, OpenVINO GPU, Windows
  or physical Safari behavior. CI's optional OpenVINO CPU coverage is distinct from
  hardware GPU validation.
