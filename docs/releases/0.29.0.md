# 0.29.0 - Portable config.json import and a merged evaluation series

This stable feature release adds a **config.json import** to the new-job and
resume forms and draws a job's recorded evaluation history as **one merged
series**. The previous stable milestone `0.28.0` is already tagged and published;
nothing was overwritten or moved.

## Delivered behavior

### Import config.json when creating or resuming a job

- New **Import config.json** action in **Forge a new strategist** and in the
  **Resume training** dialog. It reads the object written by the job exporter
  (`config.json`, or the equivalent saved configuration) from a local file.
- One shared parser maps only an explicit training-parameter schema. Every other
  field — paths, job/model identifiers, status, provenance and runtime metadata —
  is reported as ignored and never merged into the form or the API payload.
- Recognized parameters fill the editable form. Fields omitted from the file keep
  their current values, so a partial file acts as a set of overrides; explicit
  `false`, `0` and other meaningful values are preserved.
- An optimization configuration (`training` plus `trials`, `study_name`, `seed`
  and `search_space`) switches the form to tuning and restores those fields.
- Importing only fills the form: it never starts or resumes a job, and the
  imported values stay editable before submission. Malformed JSON, a non-object
  root, an invalid structure or an out-of-range recognized value fails atomically,
  leaves the previous form state untouched and names the affected fields.
- **Resume** applies imported parameters on top of the checkpoint-initialized
  values. The ruleset, network channels, residual blocks, seed and optimizer stay
  fixed by the checkpoint; a conflicting imported value is reported as a kept
  checkpoint setting rather than applied, and the target total iteration must
  still exceed the saved completed iteration. Identifiers, paths, status and
  metadata cannot replace the selected resume source.
- An imported device or inference backend is kept even when the current server or
  worker cannot provide it. The device options are now shared by both forms: this
  server disables an accelerator it does not report, a specific remote worker
  disables the accelerators it lacks, and **Any remote worker** keeps every option
  enabled so the queue selects a worker with the requested hardware. Starting with
  an unavailable target reports the platform error so the user can adjust it
  manually instead of the value being silently switched to CPU.
- The new controls and messages are available in English and German.

### Merged evaluation series

- The job **Overview** now draws a single merged evaluation curve covering every
  recorded series instead of the latest series only.
- In the **Evaluation** tab, selecting **All evaluation series** draws the same
  merged curve rather than one graph per series.
- The latest series stays the default selection and every individual series
  remains selectable on its own; single-series views are unchanged.
- The merged chart keeps each iteration's own score, so a change of opponent,
  settings or Champion incumbent is still visible as a step. Its **Effective
  evaluation settings** disclosure lists every merged series with its opponent,
  iteration range and recorded context.
- This is presentation only. No engine, API, checkpoint, evaluation or training
  logic changed.

## Changes and fixes

- Fixed the resume dialog to disable CUDA and Metal when the selected target
  cannot provide them, matching new training.
- Fixed config.json import to preserve an unavailable target instead of
  downgrading it.
- Raised the Vitest per-test timeout to 20 s so the heavy workshop and plan flows
  stay reliable on loaded hosts; request assertions are unchanged.
- Documentation and release process: every change now goes through a branch and a
  pull request; release-note filenames use the unprefixed `X.Y.Z` tag, one
  consistent H1 and the version in the title; the publish workflow documents its
  historical `vX.Y.Z.md` fallback.

PyTorch 2.14.1 CPU wheel). No GPU was exercised.

  lint/format, Prettier, mypy (33 files), TypeScript, **1,150 backend tests passed

  `config-import.spec.ts` (imports an exporter-compatible config into both forms

## Upgrade notes

No storage, database, checkpoint or protocol migration is required. Existing
jobs, models and checkpoints are unchanged, and the merged evaluation chart reads
the already-recorded history. Remote workers need no update for the import
feature. Update workers only to keep their advertised version current.

## Limitations

- The import action reads a single local `config.json`; the full job archive is
  still imported with **Import job**.
- Resume import cannot change checkpoint identity (ruleset, architecture, seed or
  optimizer) by design; start a new job to change those.
- The merged evaluation curve is a presentation of recorded scores. A step where
  the opponent, settings or Champion incumbent changed is a context change, not
  continuous improvement; it is not evidence of model strength.
- CUDA, MPS and OpenVINO GPU execution were not exercised for this release.
