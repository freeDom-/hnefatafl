# Remote worker management fixes

Revoked remote workers no longer appear in the management UI. Connection
instructions now use the correct Python module command.

## Changes

- The worker list API excludes revoked credentials while keeping online and
  temporarily disconnected authorized machines visible. Revocation immediately
  removes the worker card, workshop count and training target without waiting for
  polling. Reloading the browser or restarting the server preserves that behavior.
- Revoked credentials remain unauthorized. Worker audit records, completed
  training results, imported models and uploaded checkpoints remain retained.
- Setup instructions use `.venv/bin/python -m hnefatafl.cli worker --server URL
  --work-dir ./data/remote-worker`, with the browser's server origin and enrolled
  concurrency. The existing private token environment-variable steps remain.
  A separate worker machine must use a reachable server address rather than its
  own loopback interface; see [remote training](../REMOTE_TRAINING.md).

## Validation

- `make check` passed: **652 Python tests**, **172 frontend tests**, documentation
  links, Ruff lint/formatting, Prettier, mypy, TypeScript and the production build.
  One existing CUDA-only test was skipped on this CPU host.
- The complete real-server Chromium desktop/mobile suite passed **54 scenarios**,
  with four existing duplicate mobile scenarios skipped. The focused remote-worker
  browser run also passed all four desktop/mobile scenarios.
- Regression coverage exercises online/offline visibility, immediate revocation
  even while refresh is pending, browser reload and backend restart persistence,
  rejection of previously issued credentials on every worker route, retained
  training artifacts and generated localhost/HTTPS connection commands.
- The frozen Python lockfile install, CLI worker help and Git whitespace checks
  passed. Existing test-client deprecation and Vite chunk-size warnings remain.

## Installation and update

Use the stable `0.22.1` tag and `hnefatafl-0.22.1.tar.gz` production asset.
Managed installations can run `hnefatafl-update --version 0.22.1` after following
the [backup and update procedure](../DEPLOYMENT.md). Source installations should
check out `0.22.1`, run `make install` and `make build`, and restart the server
with their existing data directory. Keep server and worker releases aligned.

This patch introduces no schema or worker-protocol migration. Existing accounts,
credentials, jobs and model/checkpoint formats remain compatible with 0.22.0.

## Remaining limits

CUDA/MPS, physical mobile browsers and production Linux/Proxmox deployment require
separate target-host validation. The service continues to use one API process.
Functional CPU training checks do not establish model strength.
