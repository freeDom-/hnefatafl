## Milestone: Saved AI tournaments

Set up a balanced AI comparison in the browser, follow progress, and return to
saved standings and individual match replays later.

### Added

- A dedicated **Tournaments** page with a setup dialog, saved collection and
  detailed results, matching the application's light/dark appearance.
- Two independently named and configured opponents, traditional search profiles
  or compatible registered models, and size-ordered battlefield selection.
- Even game counts with alternating sides, configurable move limits and a shared
  seed. Saved opponent snapshots expose the settings used for the comparison.
- Progress, standings, results by battlefield, game lengths, decision timings and
  individual match outcomes. Wins earn one point, rules draws half a point;
  move-limit unfinished games are counted separately and receive no points.
- Read-only match replay through the rules engine, retaining all recorded moves
  independently of the original model weights.
- Stop a tournament while keeping completed matches. Delete an inactive tournament
  through a confirmation dialog, including its results and replay records.

### Persistence and lifecycle

- Tournaments run in their own worker process, keeping API/gameplay requests
  responsive. One tournament can run at a time, independently of training jobs.
- SQLite stores configuration snapshots, status, progress and completed matches.
  Results survive browser reload and server restart; interrupted runs report their
  stopped worker rather than remaining apparently active forever.
- Cancellation retains finished matches and discards the in-flight game.
  Deletion requires a stopped worker and removes only that tournament's collection
  entry and artifacts. Models, checkpoints, profiles and ordinary games remain.
- Active model references are protected from deletion until the worker stops.
  API validation checks bounds and model/ruleset compatibility without accepting
  client-supplied filesystem paths.

### Validation

- **231 Python tests**, **17 frontend unit tests** and **13 real-API browser checks
  passed**. Three redundant mobile worker checks are intentionally skipped;
  mobile tournament setup, results, replay and deletion run.
- Backend tests execute real workers and neural searches, check balanced scoring,
  explicit unfinished outcomes, partial cancellation, restart persistence, failure
  cleanup, schema upgrades and replay after model deletion.
- Browser tests reopen saved results after reload, compare replay boards against
  engine states, inspect parameters, cancel/confirm deletion and stop active runs.
  Unit tests cover independent settings, model compatibility and delayed selections.
- Ruff/Prettier, mypy/TypeScript and the production build pass.
- Desktop/mobile screenshots verify the rendered light/dark interface. Production
  startup upgrades the existing schema-2 database to 3 with all seven earlier game
  records unchanged; the new collection starts empty.

### Update and migration

Stop the service and back up the full data directory before updating. Startup
automatically and additively upgrades SQLite schema 1 or 2 to schema 3, adding
saved tournaments while retaining earlier player/model migrations. Existing
game JSON, identities, optimistic versions, models and training checkpoints remain.
Older releases reject the newer schema; restore a consistent pre-update backup
when rolling back.

```sh
make install
make build
bash scripts/start.sh
```

Use **Tournaments** in the main navigation. See `docs/TOURNAMENTS.md` for setup,
scoring, replay and deletion. Tournaments compare two opponents; automatic resume,
multi-opponent brackets and distributed scheduling are outside this milestone.
Short test runs establish correct execution and storage, not playing strength.
