# 0.21.0 - Structured AI workshop training dashboard

The selected training job now receives a wide monitoring workspace instead of
sharing half the page with a permanently expanded creation form. A compact
workshop header and collapsible creation, remote-worker and model sections keep
daily monitoring close to the top of the page.

## Delivered behavior

- Searchable, filterable, sortable job navigation; initial active/recent selection,
  stable explicit selection during polling, and an optional full-width dashboard.
- A persistent job summary with recorded progress/stage/duration, remote updates,
  errors and existing lifecycle actions/confirmations.
- Overview, Learning, Evaluation, Performance and Details tabs with keyboard
  navigation and retained analysis/range choices during live refreshes.
- Responsive SVG charts with explicit axes/units, exact keyboard/pointer values,
  quieter long histories and lazily opened accessible data tables.
- Evaluation contexts separated by opponent, effective settings and Champion
  incumbent; missing observations remain gaps and promotions are marked.
- Throughput, MCTS, GPU/inference and sequential timing groups; overlapping
  CPU/host/CUDA activity is never stacked as wall-time phases.
- Preserved model/job import/export, rename/delete, checkpoint/study resume,
  saved-parameter loading, tuning, worker management and English/German controls.
- Desktop job rail, tablet/mobile selector, touch-friendly controls, theme-aware
  colors and an existing tablet-header overflow fix.

See the [dashboard guide](../TRAINING_DASHBOARD.md) for component boundaries,
controls and chart interpretation.

## Validation

- `make check`: 611 Python tests passed, one CUDA-only test skipped; 164 frontend
  tests passed. Ruff/format, mypy, TypeScript, Prettier, documentation checks and
  the production build passed. The locked dependency check passed offline.
- Full real-server Playwright Chromium desktop/mobile suite: 50 passed, four
  existing skips for workflows covered on desktop. Includes real CPU optimization,
  checkpoint resume, job migration, model management and remote-worker progress.
- Browser fixtures cover 60-iteration running, 120-iteration completed, legacy,
  mixed-opponent/incumbent, failed, cancelled and empty workshops. All five views
  were checked at 1700, 1280, 768, 375 and 430px without page overflow.
- Keyboard tabs/disclosures, chart values, shared iteration ranges, stable polling
  selection, preserved form drafts, sparse observations, promotion events and
  missing-metric behavior have focused regression coverage.
- Wood, light and dark layouts were captured and visually inspected. Additional
  manual inspection covered Learning, Evaluation, Performance and Details; a
  2,000-line diagnostic log stayed inside a 360px pane.

## Installation and update

```sh
git fetch origin --tags
git checkout 0.21.0
make install
make check
```

No database, checkpoint, job archive, API or worker-protocol migration is required.
Keep existing data directories and full checkpoints. This release adds no charting
dependency and changes no learning, self-play, evaluation or promotion algorithms.

## Limitations

Metrics absent from older workers remain absent. Existing job-list polling still
includes server-bounded log tails; no separate log-fetch API was introduced.
CPU/browser verification does not validate CUDA/MPS hardware, long training
campaigns or model strength. Screenshots use realistic API fixtures; their GPU
and training measurements are illustrative interface data.
