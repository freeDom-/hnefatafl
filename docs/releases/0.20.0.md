# 0.20.0 — Shield maiden heuristic opponent

Adds the distinct Intermediate Shield maiden profile and `shield_maiden`
algorithm across games, custom opponents, AI versus AI, advisors, tournaments,
records and the single training evaluation selector. English/German labels are
included. The effective heuristic version is retained with agent identities and
evaluation results. Existing baseline behavior and historical identities remain.

The one-ply evaluator recognizes legal royal capture/escape geometry, independent
clear routes, exposed pieces, capture opportunities, material and containment.
It applies every candidate through the existing engine and needs no PyTorch.
Training resumption can switch to maiden without resetting learning state;
benchmark histories remain separate by opponent and effective protocol.

See [measured strength, runtime and limitations](../SHIELD_MAIDEN.md) and the
[reproduction configuration](../../configs/benchmarks/shield-maiden.json).

## Installation and update

```sh
git fetch origin --tags
git checkout 0.20.0
make install
make check
```

No database or checkpoint-format migration is required. Preserve data directories,
model copies and full checkpoints. Update remote workers to 0.20.0 before selecting
the new evaluation opponent; older workers do not recognize this algorithm.

## Limitations

A stronger weak-king opponent does not establish stronger Copenhagen siege play.
Low decision latency does not imply equal complete-game or training-evaluation
wall time. No GPU strength or performance claim is made. Selective reply search
is disabled; opponent forts, encirclement and shieldwalls are not exhaustively
searched. Win estimates remain uncalibrated heuristic values.

## Measured strength and speed

The 256-game side-balanced held-out comparison scored 86.7% Brandubh (128 games),
87.5% Tablut (64) and 54.7% Copenhagen (64). Paired 95% intervals were 81.6–91.4%,
80.5–93.8% and 48.4–62.5%; Copenhagen improvement is not established.

Matched decision latency: mean 9.723 → 9.314 ms, median 4.652 → 4.685 ms,
p95 27.908 → 27.179 ms. Richer child evaluation is offset by exact-win early exits.
Complete self-play runtime ratios were 2.64× Brandubh, 1.78× Tablut and 0.43×
Copenhagen, with different game lengths. Actual neural evaluation runtime ratios
were **3.79× Brandubh**, 0.91× Tablut and 0.89× Copenhagen (three repetitions of
eight games each). The no-increase evaluation target was not met universally;
Brandubh games grew from 65 to 266 total plies. These CPU measurements do not
promise the same trade-off for other candidates or hardware.
