## Milestone: A manageable model workshop

Models can be renamed, their training settings can be loaded into the workshop,
and saved training data can be removed independently. Tournaments now identify
participants by their model or AI profile name and retain useful model provenance.

### Model and training-data management

- Rename a model from its card. The catalog name changes while its ID, rune,
  checkpoint bytes and training metadata remain stable. Existing game and
  tournament reports retain their recorded names; new selections use the new one.
- Load recorded training parameters into the form, including advanced settings,
  without starting training. Paths and resume tokens are excluded. Review the
  loaded settings before starting; restoring weights and optimizer state still
  requires the separate resume action.
- Delete an inactive training job after confirmation, removing its saved
  checkpoints, replay state, progress and logs. Registered inference models and
  game/tournament histories remain available. The deleted checkpoint can no
  longer be resumed.
- Running workers and shared optimization-study dependencies prevent deletion.
  Remove dependent optimization jobs before deleting their source study data.
- Model cards show network width/depth, snapshot and planned iterations,
  self-play games, training MCTS budget, optimizer, learning rate and seed.
  Missing legacy metadata is labelled rather than invented.
- English and German controls cover the new workflows.

### Simpler tournament identities

- Remove the separate participant-name fields and rerolls. Neural participants
  use the model name; other participants use their AI profile name.
- Use the same persistent model/agent rune in setup, standings, match logs and
  replay. Search settings and opponent positions distinguish repeated models.
- Show the model's network and important training settings during setup and in
  saved results. Store a path-free metadata snapshot so reports retain their
  provenance after source training data or catalog models are removed.
- Older tournaments remain viewable and replayable, resolving recorded model or
  profile names where available without rewriting their stored gameplay data.

### Validation

- **327 backend tests**, **81 frontend unit tests** and **26 real-API browser
  checks pass**. Four duplicate mobile worker checks remain intentionally skipped.
  Ruff/Prettier, mypy, TypeScript and the production build pass.
- A real CPU browser workflow resumes training, renames the resulting model,
  loads its recorded settings, deletes training data and uses the retained model

- Backend checks cover active checkpoint users, shared studies, unsafe paths,

  model entries and eight rune assignments against a complete pre-update backup.

### Update and compatibility

Stop the service and back up the **complete data directory** before updating:

```sh
make install
make build
bash scripts/start.sh
```

The database remains at **schema 5**; no migration is required. Model IDs and
checkpoint formats are unchanged. Keep one API worker. Catalog renames are local
metadata: exported checkpoint files retain their original embedded names.

Training-data deletion permanently removes exact resumption state from that job.
Back up data that may be needed later. CPU smoke checks validate the workflow,
not competitive model strength; CUDA/MPS remain unverified on this host.
