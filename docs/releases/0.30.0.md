# 0.30.0 - Shared notifications and a preserved job tab

This stable feature release gives the frontend **one shared notification layer**
for transient messages and makes the training workshop **keep the active
analysis tab when switching jobs**. The previous stable milestone `0.29.0` is
already tagged and published; nothing was overwritten or moved.

## Delivered behavior

### Shared frontend notification layer

- One application-wide notification layer replaces the former per-page error
  banners. The implementation lives in
  [`frontend/src/notifications.tsx`](../../frontend/src/notifications.tsx) and is
  rendered once at the application root; individual pages no longer own
  notification state.
- A small external store exposes `notify.error(message, options?)`,
  `notify.success(...)`, `notify.info(...)`, `dismissNotification(id)`,
  `clearNotifications()`, `useNotifications()` and the `NotificationProvider`
  that renders the single viewport.
- Errors stay until dismissed. Success and informational messages auto-dismiss
  after six seconds. Identical messages are deduplicated for five seconds and at
  most three notifications are visible at once, with further messages queued and
  bounded to five entries.
- `api()` in [`frontend/src/api.ts`](../../frontend/src/api.ts) reduces server
  payloads to a readable string (a string `detail`, validation-detail arrays or a
  nested detail object), caps the text at 300 characters and falls back to a
  generic message. The shared `errorMessage(error, fallback?)` helper provides
  the same guarantee for non-API failures. Stack traces, objects and empty
  messages are never rendered.
- The viewport is fixed to the top centre with a high stacking order so it is
  never clipped by a scroll container. Native modal `<dialog>` elements paint
  above every ordinary fixed layer, so the viewport is portaled into the topmost
  open dialog while one exists and back to `document.body` otherwise.
- Each message uses `role="alert"` (errors) or `role="status"` (success/info),
  ships an accessible close button and never moves focus. Long messages wrap
  inside the viewport on both desktop and mobile.
- Migrated surfaces: the top-of-page application error banner; new-game creation
  failures (selections and retry are preserved); login, logout and
  expired-session errors; model rename, training resume, tournament creation,
  remote-worker create/revoke/override/copy and analytics-settings save
  failures; and errors reported from the hall of records, tournaments and
  training workshop through their `onError` callbacks.
- Some states stay inline because they are contextual rather than transient:
  field validation, persistent page/dialog states, the registration-unavailable
  notice and console-only diagnostics or expected cancellations. A failed form
  submission may show a concise snackbar while the form keeps its field-level
  guidance.
- The new controls and fallback messages are available in English and German.

### Preserved job-details tab

- Selecting another job in the workshop list keeps the currently open analysis
  tab (**Overview**, **Learning**, **Evaluation**, **Performance** or
  **Details**), so the same view can be compared across jobs.
- The panel always renders the newly selected job's data and actions. Per-job
  view state such as the iteration range, selected evaluation series and open
  diagnostics resets for the new job.
- Opening a job for the first time, and starting, resuming or importing a job,
  still focuses **Overview**. If a future job type does not offer the preserved
  view, the dashboard falls back to **Overview**. The selection is not stored
  across browser sessions.
- Tab handling is centralized in
  [`frontend/src/jobTabs.ts`](../../frontend/src/jobTabs.ts) (`jobTabs`,
  `defaultJobTab`, `isJobTab`, `availableJobTabs`, `resolveJobTab`). The workshop
  owns the selection, and the dashboard is keyed by job id so local analysis
  state cannot leak between jobs. Unknown or unavailable values never leave the
  tablist and tabpanel out of sync.

## Changes and fixes

- Frontend failures now surface consistently through the shared notification
  layer instead of scattered banners, including failures raised from dialogs
  where the old top-of-page banner could scroll out of view.
- Fixed a case where a preserved or unknown tab could leave the tablist and
  tabpanel out of sync; `resolveJobTab` validates the value against the job's
  available tabs and falls back deterministically.

## Upgrade notes

No storage, database, checkpoint or protocol migration is required. This release
changes only the frontend: existing jobs, models, checkpoints and remote workers
are unchanged, and workers need no update for either feature. Update workers only
to keep their advertised version current.

## Limitations

- Notifications are client-side presentation. They report a failure but do not
  retry the operation; each migrated surface keeps its existing retry and
  field-validation behavior.
- The preserved analysis tab is in-memory only and is not restored after a page
  reload or a new browser session.
- CUDA, MPS and OpenVINO GPU execution were not exercised for this release.
