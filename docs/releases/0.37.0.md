# 0.37.0 - Champion-aware adaptation and reliable large job transfers

This stable milestone adds Champion-aware learning-rate adaptation, self-play
outcome charts and reliable transfer of large training histories. It includes all
changes merged to `main` since published `0.36.0`:
[#57](https://github.com/freeDom-/hnefatafl/pull/57),
[#58](https://github.com/freeDom-/hnefatafl/pull/58) and
[#59](https://github.com/freeDom-/hnefatafl/pull/59), including their review fixes.

**Compatibility:** new job exports use **schema-3 TAR.GZ**, which older releases
cannot read; legacy ZIP schemas 1 and 2 remain importable. Controller state advances
to **version 4**, with compatible older-state loading and conservative Champion
regime resets. Database schema stays **13** and checkpoint tensor format stays
**1**. Update remote workers to **0.37.0** before assigning new work.

Full comparison: [`0.36.0...0.37.0`](https://github.com/freeDom-/hnefatafl/compare/0.36.0...0.37.0).

## Training and AI changes

### Champion-aware HyperController (#59)

- Optional online learning-rate adaptation now accepts `evaluation_opponent:
  "champion"`. Adaptation remains **off by default**; the existing minimum of four
  evaluation games and candidate-rate validation still apply. Champion remains
  unavailable as an Optuna objective because trials require a fixed reference.
- A real Champion promotion starts a new controller regime. The promoting
  evaluation belongs to the outgoing opponent and does not change the learning
  rate. The controller keeps that rate, discards predictors, observation/action
  history and counters tied to the old Champion, and restarts warm-up against the
  new one. Model weights, optimizer moments and replay are preserved.
- Duplicate or stale promotion notifications are inert: they cannot ingest the
  score again, advance counters, move the controller RNG or reset a later regime.
  Failed challenges, draws and missing observations do not trigger a reset.
- Version-4 controller checkpoints record the active Champion identity. Matching
  resumes restore their learned state; a changed or unverifiable Champion drops
  incompatible observations while preserving the effective rate. Fixed-opponent
  states from versions 1–3 remain loadable. An explicit resume learning-rate
  override still takes effect; malformed state resets only the controller.
- The Learning view shows the active Champion, current-regime warm-up/observation
  progress, lifetime promotion-reset count and the rate retained at the last
  promotion. Decision history marks each promotion boundary. Creation/resume help,
  worker-selection messages and monitoring labels include English/German copy.
- Workers advertise `hyper_adaptation_champion` in addition to `hyper_adaptation`.
  Champion-adapted jobs require both relevant capabilities, enforced for queued,
  assigned and explicitly selected workers even with a version override. The
  additional capability does not block fixed-opponent adapted jobs.

See [automatic updates](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/TRAINING.md#automatic-hyperparameter-updates)
and [remote adaptation](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/REMOTE_TRAINING.md#online-hyperparameter-adaptation).

## Training-data transfer and security

### Large, complete job archives (#58)

- **Export job** now downloads `.tar.gz` with schema 3 and `application/gzip`.
  Import recognizes the archive contents independently of the filename and still
  accepts genuine schema-1/2 ZIP jobs, including supported studies and full-state
  checkpoint resumption. Only inactive jobs and inactive study contributors can
  be exported.
- Large histories no longer share the old 16 MiB small-metadata ceiling. A bounded
  manifest and job record reference complete JSON documents stored as shared
  content-addressed chunks. Repeated reports/chunks occupy one physical copy;
  distinct database and file reports remain distinct. History is never sampled,
  truncated or rounded, and integer/float/boolean representations and signed zero
  remain distinguishable.
- Available full/best/inference checkpoints, optimizer/replay/RNG state, evaluation
  and performance histories, retained models, worker logs, study databases, trial
  artifacts and required frozen dependencies survive transfer. Import creates new
  job IDs and reuses verified model weights without changing existing catalog
  identities. Sanitization and reference rebasing can change serialized metadata
  and checkpoint bytes while preserving training values.
- Exports pin consistent inactive artifacts and study backups before doing
  serialization/compression outside global lifecycle locks. Only referenced model
  files are pinned. A required model deleted during capture causes a retryable
  conflict rather than an inconsistent archive. Cross-filesystem staging keeps
  descriptor use bounded even for more than 1,000 artifacts; unsafe snapshot
  support fails explicitly.
- One import/export is admitted at a time, before another import's multipart body
  is parsed. Competing operations receive HTTP 409 with a retry message and
  `Retry-After`, avoiding queued duplicate uploads. Capacity stays reserved through
  streaming and abandoned-worker cleanup. Failed/cancelled uploads, snapshots and
  partial downloads are cleaned up; import publication remains transactional.
- TAR members are copied into isolated staging with explicit validation. Unsafe
  paths, links, special/sparse/extended entries, conflicting or duplicate members,
  invalid JSON and checksum failures are rejected. Legacy ZIP validation remains
  in place.

### More complete diagnostic redaction (#58)

Recognized password, token, secret, credential, API-key and authorization values
are now removed completely from diagnostic strings and worker logs, including
quoted values with spaces, Unicode, escapes or newlines, JSON/environment
assignments and values split across log reads. Portable-reference diagnostics use
the same filter; structured credential fields and recognized absolute paths remain
removed. Malformed credential structures fail closed, and cleaned logs retain the
existing size cap.

This recognizes labeled credentials, not arbitrary secrets or encodings. Treat
archives containing diagnostic data as potentially sensitive and inspect them
before sharing; older exported files are not repaired automatically.

See [transfer guarantees, redaction and limits](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/TRAINING_DATA.md#moving-data-between-installations).

## UI and usability improvements

### Self-play outcomes in Performance (#57)

- Plot **Games / hour**, **Average game length**, **Attacker wins**, **Attacker win
  rate**, **Defender wins** and **Defender win rate** from recorded per-iteration
  performance data, alongside the existing metrics and iteration windows.
- Side win rates use completed games, including rules draws and excluding
  truncated games. A genuinely absent completed total can be reconstructed from a
  complete valid outcome breakdown. Contradictory, negative, fractional or
  non-finite counters are omitted instead of displayed as zero or misleading
  percentages. Missing historical outcomes stay absent; unrelated throughput
  observations remain usable.
- Empty current performance snapshots no longer hide the latest usable historical
  data. Percentage charts retain useful resolution, cap their axes at 100%, and
  format axes, legends and inspection values consistently.
- Throughput-history column headings remain visible during vertical scrolling and
  aligned during horizontal scrolling. The change is scoped to that table and
  keeps its theme-aware background; German win-rate labels are included.

### Complete imported analysis and safe live refreshes (#58)

- The workshop requests a compact import response, selects the new job immediately
  and loads its history through the existing shared detail request, with the
  localized **Loading history…** state. Imported best-model associations remain
  available to catalog-name search, including deduplicated models.
- Already-loaded nested histories, evaluation/performance analysis, tuning metadata
  and best-model annotations survive compatible navigator refreshes while current
  status, counters and timestamps continue to update. New live phase counters
  replace old phase counters, and cleared between-trial timers stay cleared.
- Run/trial identity changes discard incompatible reports instead of mixing
  histories. Model details are retained only for the same known model ID;
  replacement or removal cannot inherit another model's name/path. A stale detail
  response triggers at most one immediate replacement request, then uses the
  existing localized refresh error if identities keep changing.
- Imported navigator summaries are cached as bounded projections rather than
  reopening large histories on every poll. Full detail and original database/file
  reports remain available for analysis and lossless re-export.

See [Performance](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/TRAINING_DASHBOARD.md#analysis-views)
and [job transfers](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/TRAINING_DATA.md#moving-data-between-installations).

## API and compatibility considerations

- Job export changes from ZIP to TAR.GZ. Clients that assume `.zip` or
  `application/zip` must accept the new download name/type. The importer accepts
  both new TAR.GZ and legacy ZIP archives.
- `POST /api/training/jobs/import` keeps HTTP 201 and a **complete job response by
  default**; `?summary=false` explicitly selects it. `?summary=true` opts into a
  compact job with its ID, configuration, status, resume information, model
  associations and bounded progress. Full reports remain at
  `GET /api/training/jobs/{id}`. The workshop uses the compact option explicitly.
- New archives retain the 512 MiB compressed/upload limit, separate 1 GiB physical
  and reconstructed-data budgets, and a 2,048-member ceiling. Reconstructed JSON
  documents may use the 128 MiB artifact budget; manifests/small job records retain
  the 16 MiB guard. Legacy ZIP imports retain their 16 MiB JSON and 200:1 per-entry
  ratio guards. Deduplicated references count toward the full logical-data budget.
- No database or worker-protocol migration is introduced. Optional imported-summary
  metadata does not replace retained full reports. Existing exact worker-version
  matching remains; a version override cannot bypass Champion adaptation's
  capability gate. No training configuration key is removed or renamed.

## Measured performance and limits

The documented original archive-migration fixture uses a real one-iteration CPU
checkpoint and **1,000 synthetic metric iterations**, not 1,000 optimizer updates.
Its history-heavy archive shrank from **22,084,180 bytes** (stored ZIP) to
**131,926 bytes** (schema-3 TAR.GZ), while export/import took approximately
**12% / 10% longer**. This fixture compresses especially well and does not predict
checkpoint-heavy jobs. See [migration measurements and raw samples](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/benchmarks/job-archives.md).

Later review measurements use different intermediate baselines. The explicit
compact workshop import reduced initial-response bytes and observed browser heap
on large synthetic reports; **peak server memory did not improve**. The restored
default full-response API is deliberately excluded from that compact-response
comparison. See [the final compatibility measurements](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/benchmarks/job-archive-final-review.md).

The final sanitizer review measured ordinary 64 MiB metric logs at
**5.806 → 3.612 seconds**, and credential-dense logs at **5.631 → 7.833 seconds**:
complete redaction is more expensive for dense credentials. Streaming sanitizer
allocation stayed below 0.4 MiB in the measured 1/8/64 MiB cases, but complete JSON
reconstruction is **not constant-memory import**. Concurrent CPU smoke samples
showed no additional observed throughput regression with overlapping ranges;
they do not establish a training speedup or zero contention. See
[security-review evidence](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/benchmarks/job-archive-security-review.md).

## Upgrade and installation

1. Stop/cancel training and tournaments, pause remote claim loops and unmanaged
   CLI writers, and take a complete stopped-writer backup of the data root and
   protected configuration. Retain matching `0.36.0` code and older exports.
2. After this stable release and its verified source asset are published:

   ```sh
   hnefatafl-update --check
   hnefatafl-backup
   hnefatafl-update --version 0.37.0
   ```

   On Proxmox, prefix these commands with `pct exec <CTID> --`. Fresh installations
   follow [Deployment](https://github.com/freeDom-/hnefatafl/blob/0.37.0/docs/DEPLOYMENT.md).
   Use attached `hnefatafl-0.37.0.tar.gz`, not GitHub's automatic source archive.
3. Confirm readiness and schema **13**. No database migration or checkpoint tensor
   format change is required. Update remote workers to **0.37.0**; Champion-adapted
   jobs additionally require `hyper_adaptation_champion`.
4. Upgrade the destination before transferring schema-3 job archives. Older
   releases cannot import them, so retain legacy ZIP exports/full backups when
   rollback or older destinations matter. Inactive-study/frozen-model dependency
   checks and historical study-identity restrictions continue to apply.
5. On a Champion resume, review visible controller reset/warm-up information.
   Older or changed Champion regimes may restart controller learning while keeping
   the effective rate, model and optimizer state. Frequent promotions intentionally
   cause more warm-up; fixed-opponent adaptation remains available.

## Limitations

- Champion adaptation optimizes a changing evaluation proxy within separate
  regimes, not Elo or held-out playing strength. No stronger-model claim or new
  held-out strength benchmark accompanies this feature.
- Archive size/document/member budgets still apply. Import may need substantial
  memory for reconstruction, validation and SQLite serialization; it is neither
  unlimited nor constant-memory. Large-replay, shared-disk and GPU throughput were
  not benchmarked, and measured browser heap excludes native/DOM/GPU memory.
- Redaction is heuristic; arbitrary diagnostic data can remain sensitive. Safe
  snapshots require suitable filesystem pinning support, and a concurrent required
  model deletion requires retry. Existing single API-worker deployment remains.
- Hardware-specific skips are distinct from functional CPU coverage. Chromium
  desktop/mobile emulation is not physical Safari validation; CUDA/MPS/OpenVINO
  GPU behavior and playing strength were not established by these measurements.
