# 0.19.0 - Configurable training evaluation and reliable model selection

## Delivered behavior

Training selects exactly one opponent: existing Shield bearer heuristic, existing
Jarl alpha-beta search with editable depth/deadline, or the saved neural Champion.
Start and Resume expose evaluation frequency, games, move/simulation/time limits
and conditional Jarl/promotion settings in English and German. Resume continues
full learning state and keeps the existing preset as provenance without a selector.

Fixed benchmarks keep independent immutable best snapshots by effective protocol
identity; ties keep the earlier record. Saturation is flagged. Champion evaluation
uses equal neural budgets and side-swapped seed pairs, with per-side outcomes.
Promotion requires complete games, a minimum pair count and a one-sided paired
Hoeffding lower bound strictly above 50% plus the configured margin. Small leads,
ties, losses, failed/cancelled matches and incomplete games retain the incumbent.
Candidate learning continues after rejected promotion.

Defaults preserve prior evaluation cadence and board budgets. Champion policy
defaults to 95% confidence, at least 12 pairs and zero additional margin above
50%; the base two-game smoke budget cannot promote. Users should normally select
48–64 games at intervals around ten iterations for Champion experiments.

## Checkpoints, history and execution

Tensor checkpoint format 1 remains supported. New full checkpoints add training
state version 2 and versioned benchmark/champion data. Legacy baseline score and
best snapshots retain their meaning; migration is in memory and never rewrites
the source. Switching opponents preserves weights, optimizer buffers, replay,
RNG/scaler state, completed iterations, history and model associations. A legacy
saved best can initialize the first provisional Champion without invented games.

The workshop separates curves by effective benchmark settings and Champion
incumbent, and shows side bias, draws, truncations, promotion events, accepted
champion iteration, fixed records, duration and loss history. Skipped evaluation
points stay missing. Only the selected evaluator runs at scheduled multiples and
the final optimized iteration; checkpoint writes do not trigger extra matches.
Optuna retains a fixed Shield bearer objective and rejects moving objectives.

Local/remote subprocess stdout now logs bounded incremental summaries rather than
repeating all history and game arrays. Persistent JSON/checkpoints retain history;
large remote progress histories use indexed chunks with idempotent retries.
Actual self-play work diagnostics include requested/completed simulations, side
wins, immediate-win shortcuts and deadline cutoffs alongside existing batch,
throughput, GPU allocator and phase timing metrics.

## Installation and update

Back up retained data, update server and workers to the same release, then run
`make install`, `make check` and your normal production startup. Existing full
`last.pt` files resume through the Workshop or CLI. No database migration or
source-checkpoint rewrite is required. New examples are
[Jarl training](../../configs/train-evaluation-jarl.json) and
[Champion resumption](../../configs/train-evaluation-champion.json).

## Limits and interpretation

Evaluation remains sequential; self-play batching assumes one model and is not
reused across different neural identities. No GPU speedup or stronger-model claim
is made. Jarl cost depends on search budgets and hardware. Fixed benchmark score
improvements are records, not statistical evidence of universal neural superiority.
The conservative Champion bound is per comparison, assumes independently seeded
pairs, and is not a multiple-testing guarantee. Wall-clock cutoffs can affect
reproducibility. Inference exports contain the selected benchmark best/champion,
which can be older than the current candidate in resumable `last.pt`.

CUDA/MPS execution and the user's production RTX 3060 checkpoint are unavailable
on this CPU host; migration is verified with a representative iteration-100-style
legacy checkpoint and actual subsequent optimizer updates. Safe checkpoint size
limits remain 128 MiB, including retained snapshots and replay.
