# 0.8.0 - Four-player tournaments and clearer records

Compare up to four AI opponents in a balanced round robin and explore saved
results with sortable, filterable, compact Hall of records tables.

### Added and improved

- Tournament setup supports two, three or four opponents, with independent
  profiles, parameters and compatible models. Every unordered pair plays the
  chosen even number of games on each selected battlefield, swapping sides.
- Progress totals include all pairings. Standings count only each opponent's
  participation, and battlefield results label wins by opponent. New match
  records identify both players explicitly; older two-player replays still work.
- Every column in **Results by battlefield** and **Player & AI performance**
  sorts ascending/descending, using numbers for counts, rates and average moves.
  Headers expose the current sort order to assistive technology.
- A player-column search filters names and visible AI summaries. A separate
  recorded-games search matches either participant or saved profile/model name.
  Searches are case-insensitive and independent of each other and summary totals.
- AI statistics use one compact table row, matching human row height. The second
  line summarizes profile, algorithm and main budgets. The parameter button to
  the left opens all recorded settings in a keyboard-accessible dialog.
- Fresh browsers use **Carved wood** tokens on **Old walnut** boards. Valid
  existing preferences are preserved; missing/invalid fields use the new defaults.

### Selected king design

Three carved-wood king concepts are provided in `docs/designs/king-options.md`:
**Fjord Diadem**, **Raven Crown** and **Raven Standard**. The first two use northern
crown motifs; the third is a raven banner emblem. The selected design is
**1 · Fjord Diadem**, a low three-peak northern circlet with an interlaced band.
It is rendered as scalable SVG on the carved-wood king. Classic stones and Viking
figures keep their existing king artwork. The concept sheet retains all three
alternatives for reference.

### Validation

- **264 Python tests**, **48 frontend unit tests** and **20 real-API browser checks
  passed**. Four duplicate mobile worker checks are intentionally skipped;
  responsive records and four-opponent tournament flows run on mobile.
- Tournament tests verify three/four-player pairings, equal side assignments,
  per-opponent participation, actual worker results, retained replay and legacy
  two-player compatibility. Four opponents schedule 12 matches at two games per pair.
- Record-table checks cover numeric ascending/descending sorts, independent
  case-insensitive searches, compact AI rows and full parameter inspection.
- Appearance checks verify wood/walnut defaults and retain valid saved preferences.
  The selected king was inspected on 7×7 and 11×11 boards; desktop/mobile
  appearance flows passed again after implementation. Ruff/Prettier,
  mypy/TypeScript and the production build pass.
- Production startup serves v0.8.0 and preserves all seven existing games exactly
  against a pre-update digest. A full data backup was made before restart.
- The database remains at schema 3; no data migration is required. See
  `docs/VALIDATION.md` for scope and reproducibility instructions.

### Update and compatibility

The database remains at schema 3. Existing games, model references and saved
two-player tournament reports do not require migration. The tournament `games`
setting now explicitly means games **per pairing per battlefield**; its total
is unchanged for two players. Four opponents at two games on one battlefield
schedule 12 matches, six per opponent. Viewing new three/four-player reports
requires a client from this release or later.

Stop the service and back up the complete data directory before updating:

```sh
make install
make build
bash scripts/start.sh
```

Run one API worker as documented in `docs/DEPLOYMENT.md`. Cancelled tournaments
retain completed matches, move limits remain explicit unfinished results, and
saved preferences continue to take priority over new-browser defaults.
